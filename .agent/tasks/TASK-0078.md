## Goal

A gate run uses the local Testcontainers Postgres (WSL daemon) unless the human has explicitly
confirmed the hosted database. Today `ci.ps1` silently prefers `~/.gras/pg-test.txt`, the hosted Neon
pooler in us-east-2, over the container. On 2026-09-17 that turned a ~4-minute integration stage
into 45+ minutes, and the ledger claimed local runs were container-backed.

None.

## Acceptance criteria

- [x] New `ci.ps1` switch **`-UseHostedDb`**. `Initialize-PostgresTestConnection` reads
      `~/.gras/pg-test.txt` **only** when that switch is passed. Without it, the file is ignored even
      when present and non-empty.
- [x] An explicitly set `$env:POSTGRES_TEST_CONNECTION` still wins, so CI's service container keeps
      working (`backend-ci.yml:145`). **But** outside CI (`$env:GITHUB_ACTIONS` unset), an env var whose
      host is not `localhost`/`127.0.0.1`/`::1` **fails the gate** unless `-UseHostedDb` is passed. A
      hosted connection must never arrive by an ambient env var either.
- [x] ~~**Pre-flight, before the integration stage** and only when the run is container-backed: probe the
      Docker endpoint `DatabaseAvailability` resolves (same resolution, not a second copy). If it is
      unreachable, **FAIL the gate** (never skip, never fall back) with exactly this guidance:
      `Local container runtime unreachable at <endpoint>. Do NOT fall back to the hosted database
      without the human's confirmation. Ask them to check the WSL Docker daemon; re-run with
      -UseHostedDb only after they confirm.`~~ **WITHDRAWN by ruling, see Log**; replaced by failure-path guidance.
- [x] The first line of every run names the database source: `Integration database: local container
      (<endpoint>)`, `... hosted (from ~/.gras/pg-test.txt, confirmed via -UseHostedDb)` or
      `... explicit POSTGRES_TEST_CONNECTION (CI)`. Never the connection string, on any path.
- [x] `-SkipIntegration` runs need no database and no pre-flight.
- [x] `postgres-test-connection.tests.ps1` extended: file ignored without the switch; used with it;
      explicit env var wins; non-local env var outside CI rejected; unreachable probe fails with the
      message. **Each new assertion shown to fail against the pre-change resolver** (standing lesson:
      a check that cannot fail is not a check).
- [x] Doc comments in `postgres-test-connection.ps1`, the `ci.ps1` header and `DatabaseAvailability.cs`
      describe the new order; nothing still says the file "wins" by default.
