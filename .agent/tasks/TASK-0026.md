## Goal

The backend produces the same gate result on any machine, because what the gates DO is determined
by committed, pinned versions rather than by whichever SDK happens to be installed.

## Why TASK-0024 was not enough

TASK-0024 set `rollForward: latestFeature` → `latestPatch` and the next CI run still failed two
SDK-coupled behaviours that pass locally on 10.0.100:

- `CA1873` at `RequestLoggingBehavior.cs(84,21)` — **inside** the `IsEnabled` guard TASK-0024 added.
- `dotnet test` still reports `The argument <dll> is invalid. Please use the /help option`.

The pin was verified by SDK-resolution semantics, not by reproduction, and that was too weak.
`AnalysisLevel` and the test bridge can both change **within** the 10.0.1xx patch band, so no
`rollForward` value closes this.

**The actual root cause is in the repo, not in `global.json`:** `Directory.Build.props:19` sets
`<AnalysisLevel>latest-All</AnalysisLevel>`. `latest` means "whatever this SDK ships". The build's
rule set is therefore a property of the machine, which is exactly what a lockfile exists to prevent.

## Acceptance criteria

- [x] **Fix CA1873 version-independently** by hoisting inside the existing guard:
      `if (logger.IsEnabled(LogLevel.Information)) { var elapsedMs = (long)Stopwatch…; BehaviorLog.RequestCancelled(logger, requestName, elapsedMs); }`
      This keeps the skip semantics AND matches the success path four lines up, which passes
      precisely because it hands over a local. The guard alone does not satisfy the analyzer:
      `BehaviorLog.RequestCancelled` is a static `[LoggerMessage]` method taking `logger` as a
      PARAMETER, so the analyzer cannot tie `logger.IsEnabled(...)` to it.
- [x] **Analyzer behaviour pinned to a committed version, not the SDK.** Reference
      `Microsoft.CodeAnalysis.NetAnalyzers` at an exact version through Central Package Management
      and replace `latest-All` with a pinned equivalent. State what you chose and confirm the
      SDK's built-in analyzers no longer decide the rule set. **Do not weaken the rule set to pass**
      — `-All` severity coverage must be preserved; only its VERSION becomes fixed.
- [x] **The test-runner bridge is DECLARED, not inherited.** `dotnet test` is passed VSTest-style
      arguments (`--settings coverlet.runsettings`, `--logger trx`, `--results-directory`) while
      `xunit.v3` is Microsoft.Testing.Platform-native and `xunit.runner.visualstudio` provides the
      VSTest bridge. Which path runs currently depends on the SDK. Make it explicit
      (e.g. `TestingPlatformDotnetTestSupport`) so the invocation and the arguments agree on ANY
      SDK. Say which mode you chose and why. **`.trx` output and coverlet coverage must both keep
      working** — the §9 gates and CI's not-skipped assert depend on the `.trx`.
- [x] `./backend/scripts/ci.ps1` green locally, `SUMMARY` pasted, `Skipped: 0`.
- [x] Contract hash unchanged. If it moves, **STOP and report the diff** — do not promote.
