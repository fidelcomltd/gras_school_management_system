## Goal

The office approves a pending admission and the pupil becomes a real pupil: a registration number
is issued, the first enrolment opens in the chosen arm, and status becomes `active` — all in one
transaction, and a retried request never issues a second number. Declining sets `withdrawn` and
burns no serial.

## Contract delta

- `POST /admissions/{id}/approve` — **`Idempotency-Key` header REQUIRED** (6.5.17). Body: `armId`
  (required), `assessmentResultRemarks` (required where the record says an assessment was required),
  `headOfSchoolConfirmed` (**required, and must be `true`** — appendix B question 26), and
  `headOfSchoolName` (optional; **defaults from settings**, see the notes). Response: the pupil with its issued
  `registrationNumber`. Privilege `pupil.admission.approve`. 409 on an already-approved record.
- `POST /admissions/{id}/decline` — body `reason` (required). Sets `withdrawn`. Privilege
  `pupil.admission.approve`. No number, no enrolment, no serial consumed.

## Acceptance criteria

- [x] **The counter is a row lock, never a maximum query.** `INSERT INTO registration_counter
      (counter_key, last_serial) VALUES ($1, 1) ON CONFLICT (counter_key) DO UPDATE SET last_serial
      = registration_counter.last_serial + 1 RETURNING last_serial`. **A `MAX(serial) + 1` or a
      `COUNT(*)` anywhere in this card is a review blocker** — 6.5.10 says counting existing pupils
      is the mechanism that produces duplicates.
- [x] Counter key comes from `RegistrationCounterPartition.Resolve` against the SAVED
      `serial_reset` — the admission year under `per_year`, `ALL` under `continuous`. Both proven.
- [x] **The year is `admission_record.date_admitted`'s year, not today's.** A test approves a
      record dated September 2026 with the clock at January 2027 and asserts `2026` in the number.
- [x] The abbreviation, separator and serial width are read from settings AT ISSUE and frozen into
      the stored string. A test changes the abbreviation afterwards and asserts the issued number
      is unchanged.
- [x] **Concurrency proven, not asserted:** two approvals racing on one counter key produce two
      different serials. One test, two concurrent transactions, no sleeps.
- [x] `Idempotency-Key` replay returns the FIRST response and issues no second number, proven by a
      test asserting the counter advanced exactly once.
- [x] Unique-index violation on `pupil.registration_number` retries the whole transaction up to
      **three** times, then fails with verbatim `Could not issue a registration number. Try again.`
- [x] Approval in ONE transaction: status `active`, number issued, section J written, enrolment
      opened in `armId` effective from the later of the admission date and the session start date
      (6.5.11). Nothing half-written on failure, proven by a rollback test.
- [x] **Blocking conditions**, each with its own test and its own error naming the step: no arm for
      the level in the active session; no active term (verbatim `No term is currently active. Open
      a term before approving admissions.`); a required assessment with no recorded outcome;
      declaration not signed. Capacity is checked per 6.4.6 — over capacity needs
      `arm.capacity.override`, and is a WARNING there, not a rejection.
- [x] Decline sets `withdrawn`, issues no number, and leaves `last_serial` untouched — asserted
      directly against the counter row, not inferred from the absence of a number.
- [x] `abbreviation.issuedCount` now returns a real count instead of `null` — this card is that
      drift entry's named trigger. The count is of ISSUED numbers, so it reads the pupil table, not
      the counter (a corrected or declined record must not inflate it).
- [x] **`headOfSchoolName` defaults from `settings.head_teacher_name`** when the body omits it —
      6.5.9's "Defaults from settings", and the named trigger of a live drift entry. A supplied
      value still wins. Proven both ways: omitted takes the setting, supplied overrides it.
- [x] **`headOfSchoolConfirmed` false blocks approval**, with its own test and an error naming
      section J. Nothing is written, and no serial is consumed.
- [x] `openapi.json` regenerated; additive only; `contract-guardian` agrees.

## Notes for the implementing agent

**The counter half is already built and you must not rebuild it.** `Domain/Settings/
RegistrationCounter.cs`, `RegistrationCounterPartition.cs` (`Resolve` and `ContinuousKey`) and
`RegNumberSerialReset.cs` all shipped with TASK-0005c, and `IRegistrationCounterRepository` already
has `GetLastSerialAsync` — a READ, used by `GET /settings/reg-number/preview`. What is missing is
the atomic increment. Add it beside the read, on the same interface.

**The formatter likewise has a twin.** `GetRegNumberPreviewQueryHandler` already composes a sample
number from the same four settings. The real issue path must produce a byte-identical string for
the same inputs — if the preview and the issued number can ever disagree, the preview is a lie.
Factor one formatter and have both call it rather than writing a second.

**Idempotency:** `Domain/Idempotency/IdempotencyRecord.cs` exists. Use it. Do not invent a second
mechanism, and do not settle for "the unique index will catch it" — the index is the backstop
(criterion 7), not the idempotency mechanism.

**The enrolment is `Enrolment.Open(id, pupilId, armId, effectiveFrom)`** from TASK-0059, which
enforces one open row per pupil with a partial unique index. Approval is the first legitimate
caller. `Pupil.Create` sets `RegistrationNumber = null` (`Pupil.cs:85`) and no edit path exists —
this card adds the ONLY path that writes it.

**Two drift entries fire on this card besides `issuedCount`, both in `drift/2026-Q3.md` under
`## 2026-09-15 (TASK-0062)`.** Gap 2 — `headOfSchoolName` has no settings-derived default — is a
genuine spec deviation and is now acceptance criteria 13. **The orchestrator rules the source to be
`settings.head_teacher_name`**: it is the only field of that shape in 6.2.3, and 6.5.9 says the
default exists without naming it. Flagged to the human as a ruling, not a discovery; if it comes
back wrong it is one line. Gap 3 — `admission` is null on every pupil read path but the create
response — is NOT yours to fix, but read it before you shape the approve response: if you find
yourself needing the record on a read path, that is the gap, and it belongs in your closing note
rather than in this card's diff.

**Gates.** `.agent/rules/gates.md` section 1: `dotnet test --filter`, report counts, stop. The
orchestrator runs `ci.ps1`.
