## Goal

A class teacher opens their arm's readiness screen and sees exactly what still stops submission: a grid of pupils against subjects
(complete / partial / empty), the counters, and the pupils who left during the term, grouped apart. When nothing is missing and the
results are freshly computed, the teacher submits and the set moves to Awaiting Approval. From then on marks, ratings, attendance and
the class teacher's remark are locked. The "freshly computed" part has to be trustworthy, so every event §6.2.9 and §6.7.11 name now
sets `needs_recompute`, not only mark saves.

## Rulings (human, 2026-09-21): both went with the recommendation

- **The head teacher's remark does NOT gate submission.** It is a publication precondition (§6.7.9), and readiness reports it as an
  informational fifth counter. This departs from the §6.7.12 amendment's gate list and is recorded as drift.
- **The recompute triggers are built in this card, in stage A, before submit exists.** The pupil-transfer trigger is deferred to
  whichever card builds transfers, because nothing closes an enrolment today.

## Contract delta (approved)

1. `GET /api/v1/arms/{armId}/readiness?termId=`, operation `GetResultSetReadiness`, needs `result.view` arm-scoped. It is arm-routed, like every sheet,
   so it answers for a Not started arm too (`resultSet: null`, everything missing). It departs from §6.7.13's `/result-sets/{id}/readiness`
   for the same reason the score sheet did. The response is `ResultSetReadinessDto`:
   - `armId`, `termId`, `resultSet: ResultSetSummaryDto|null` (the existing schema; reuse it, do not redeclare it)
   - `subjects: [{subjectId, name}]`: the subjects in effect, in the §8.1 resolver's order. `componentCount: int` is the number of
     parts per mark cell, meaning the non-exam components plus the exam.
   - `pupils: [{pupilId, registrationNumber, displayName, marks: [{subjectId, status, filledParts}], ratingsComplete,
     attendanceComplete, classTeacherRemarkPresent, headTeacherRemarkPresent}]`, surname order. `status` is the string enum
     `Complete | Partial | Empty`. `marks` is parallel to `subjects`.
   - `leftDuringTerm: [{pupilId, registrationNumber, displayName, leftOn: date}]`: enrolment `EffectiveTo` inside the term's dates.
   - `counters: {marks, ratings, attendance, classTeacherRemarks, headTeacherRemarks}`, each `{complete: int, total: int}`. Marks
     count cells (pupil × subject); the others count pupils.
   - `blockers: [{code, message}]`, where `code` is a string enum listed in AC B3. `canSubmit: bool` is true iff `blockers` is empty
     and the state is Draft or Returned for Correction.
2. `POST /api/v1/result-sets/{resultSetId}/submit`, operation `SubmitResultSet`, needs `result.submit` scoped `ResultSet`, like `ComputeResultSet`. It requires
   CSRF, ACCEPTS but does not require `Idempotency-Key`, and uses the sensitive rate-limit policy. `200 SubmitResultSetResponse
   {resultSet: ResultSetSummaryDto, submittedAt}`. `422 ResultSetNotReadyProblemDetails`: ProblemDetails plus `errorCode`, `traceId` and
   `readiness: ResultSetReadinessDto`, the same body the GET returns, so the screen needs no second call (§6.7.5). **This is the
   contract's first typed problem extension: declare it with `.Produces<T>(422, "application/problem+json")`, because a type-less
   `Produces` silently drops `content` (TASK-0049).** `409` when the state is not Draft or Returned, or the term or session is closed.
   An unknown id is 403 (TASK-0071 ruling). There is no 404.

Error codes use the `result_set.*` form that `ComputeResultSetHandler.cs:56-62` uses. Grep it, do not invent a style.

## Acceptance criteria

**Stage A: recompute triggers and the result_set lock. The contract does not move.**
- [ ] A1. A save through any of the 7 §6.2.9 handlers (`Settings/UpdateGrading`, `ResetGrading`, `UpdateAssessment`, `UpdateResultRules`,
      `UpdateRatingScales`, `UpdateDevelopmentDomains`, `UpdateTraits`) sets `needs_recompute` on every result set in the active
      session that is not Published, in the same transaction as the save.
- [ ] A2. A change through `SaveSubjectMappingGrid`, `CopySubjectMappings`, `PrefillSubjectMappings`, `CreateSubjectException` or
      `DeleteSubjectException` flags every non-Published set whose arm's in-effect subject list it can change. If you find any
      OTHER handler that can change the §8.1 resolver's output, report it and do not wire it silently.
- [ ] A3. A flagged set in Returned for Correction drops to Draft (§6.7.11, the System row). Awaiting Approval and Approved keep their
      state and only gain the flag. Each state change is audited, with `before_json`/`after_json`.
- [ ] A4. **One lock rule:** every writer of `result_set.state` or `needs_recompute` (compute, the flaggers, submit), and every
      sheet save that checks state (score, void, trait, development, attendance, class-teacher remark), first takes a row lock
      on the result set. Flaggers lock in id order, to avoid deadlocks. Proven by two real-concurrency integration tests:
      a settings save racing compute ends with the flag set, and (stage B) a score save racing submit either lands before the
      submit or is refused with 409.
- [ ] A5. Unit tests cover which states are flagged and which move. An integration test covers one settings save and one
      mapping change end to end.

**Stage B: readiness and submit (delta items 1 and 2)**
- [ ] B1. Mark completeness counts each part: every non-exam component key present, and an exam mark OR `exam_absent`. A blank is never
      a zero (§6.7.4). Voided rows count as empty. A subject mapped mid-term shows as an empty column (edge case row 5).
- [ ] B2. Ratings follow R1-A: a pupil is complete when every active trait has a point (only when `section.ratesTraits`) AND every
      active development indicator of the section's domains has a point. Indicator comments are never required. Attendance is
      complete when `timesPresent` is non-null AND `timesSchoolOpened` is set AND present ≤ opened (the 2026-09-19 race drift).
- [ ] B3. Blocker codes, in this order: `marks_incomplete`, `ratings_incomplete`, `attendance_incomplete`,
      `class_teacher_remarks_incomplete`, `not_computed` (`computed_at` null), `needs_recompute`, `form_teacher_missing` (no form
      teacher, or the account is not active), `times_school_opened_missing`. The head teacher's remark is never a blocker.
      Each message uses §6.7.5's and §6.7.12's wording where one exists.
- [ ] B4. Left-during-term pupils are excluded from every counter and from the gate. Seed them through `Enrolment.Close` in tests.
- [ ] B5. Submit re-evaluates under the row lock, then sets Awaiting Approval, `submitted_at`/`submitted_by`, and clears `return_reason`.
      This covers both Draft→AA and Returned→AA. The event is audited with `before_json`/`after_json`. After submit, every sheet save
      except the head-teacher remark returns 409. That behaviour already exists, and a test proves it for all five sheets.
- [ ] B6. The 422 body's `readiness` equals the GET's body for the same set, proven by one test comparing both. `OpenApiExamples.cs`
      carries an example for each new schema.
- [ ] B7. Nursery and primary arms each pass and each fail the gate in their own terms, one integration test each.

**Both stages**
- [ ] Gates: the whole unit project. Integration is scoped with `-IntegrationFilter` to the new classes plus
      `ResultSet|ScoreSheet|TraitRating|DevelopmentRating|Attendance|Remark|Settings|SubjectMapping`, on the local container.
      Never the full gate. Report the counts. Never push or commit to `main`.
