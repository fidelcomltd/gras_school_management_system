## Goal

A clerk opening a pending applicant to approve them must choose an arm, and the arm selector is
`GET /arms?sessionId=&levelId=`. Neither id is reachable today: the queue row carries
`levelAppliedFor`, a display *name*, and `admission` is `null` on every pupil read path. `PATCH
/admissions/{id}` returns the record but is a write on the wrong privilege. **TASK-0064 is blocked
on exactly this and shipped its approve dialog as a stub** — this card unblocks the only screen
that reaches admission approval.

## Contract delta

- `GET /api/v1/admissions/{id}` — new. `id` is the PUPIL id, the same identity `PATCH
  /admissions/{id}` and the queue already use. Response: `AdmissionRecordDto`, the same shape
  `PATCH` already returns — **reuse it, do not define a second**. Privilege `pupil.view`,
  SCHOOL-WIDE only, for the reason the queue is school-wide only: a pending record has no arm, so
  an arm-scoped grant has no reach. 404 when `id` does not name a **pending** pupil — the same rule
  and the same message `PATCH /admissions/{id}` already applies. No write, no audit-on-read.

## Acceptance criteria

- [ ] `GET /api/v1/admissions/{id}` returns `AdmissionRecordDto` for a pending pupil, carrying
      **`sessionId` and `classAdmittedInto`** — the two opaque ids TASK-0064 needs. Asserted by id,
      not by display name.
- [ ] 404 for an approved pupil, a declined pupil, and an unknown id — three tests, the same

- [ ] The response is byte-identical to what `PATCH /admissions/{id}` returns for the same record —
      one mapper, one shape. A test asserts the two agree.
- [ ] Nothing is written: no audit row, no `updated_at` bump. Asserted, not assumed.
- [ ] `openapi.json` regenerated; **additive verified mechanically** — every existing schema's
      `required` array and every property type unchanged. Report the before/after hash.

## Notes for the implementing agent

**This is a read twin of an existing write.** `UpdateAdmissionRecordHandler` already loads the
record, already enforces pending-only-404, and already maps through `AdmissionRecordMapper`. Your
handler is that one with the mutation removed. If you find yourself writing a second mapper or a
second pending check, stop — you are duplicating, and the two copies will diverge.

**Do not widen the privilege.** It is tempting to make this arm-scoped like `GET /pupils`, which
admits an arm-scoped caller to an honest empty page. That reasoning does not transfer: this is a
single-record read, so "empty" would be a 404 that lies about existence. `ListAdmissionsQueue`
chose school-wide-only for this reason and this route follows it.

**Keep the diff small.** This is one query, one handler, one endpoint registration and its tests.
If it exceeds ~250 lines, something has been duplicated.
