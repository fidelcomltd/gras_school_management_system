# TASK-0004 — Wire the OpenAPI client generator and the typed API layer

Owner: frontend-dev
Depends on: —
Contract impact: none (consumes the committed contract; changes nothing on the wire)
Status: done

## Goal

Close the last gap in the contract pipeline. `contracts/openapi.json` has existed since
2026-08-08 and `frontend/src/api/` is still empty, so the frontend currently cannot call the
backend without guessing across the boundary — the one thing CLAUDE.md forbids outright. When
this lands, a backend contract change propagates to the frontend by running one script, and a
hand-edited client is a detectable blocker rather than an invisible one.

## Contract delta

None. This card consumes `contracts/openapi.json` exactly as committed. It must not require any
backend change. If the committed contract turns out to be unusable as-is, **stop and report** —
do not work around it in the client.

## Out of scope

- Any feature UI, screen, route or business logic. This card wires a pipeline; it ships no
  product surface.
- The frontend CI workflow — root-level CI is orchestrator-owned (§11). Report the exact
  commands CI should run and the orchestrator writes the workflow.
- Deleting `src/screens/scaffold-status/`. It goes when the first real screen lands, not here.
- Touching `src/lib/auth/`. The carrier is decided (HttpOnly cookie + CSRF) and the existing
  bearer implementation is therefore known-wrong code — but replacing it is TASK-0003, not this
  card. Layer over the transport as it stands; do not start the rewrite, and do not build
  anything that depends on the bearer seam surviving.
- Adding `react-hook-form` or any other dependency beyond the generator. Dependency additions
  need their own justification in a card (§8).

## Notes for the implementing agent

Read `.agent/STATE.md` first and append to it last (§4.1). Then `frontend/HANDOFF.md` — it is
the previous frontend session's own account of what exists and why, including why `src/api/` was
deliberately split from `src/lib/http/` (decision 3) and what `src/api/README.md` already
records about the intended pipeline.

The current contract surface is small — `/api/v1/reference/ping`, `/api/v1/reference/records`,
`/api/v1/reference/whoami`, `/health/live`, `/health/ready`. That is the point: prove the
pipeline on a trivial surface now, so that when the real endpoints arrive from TASK-0002 and
TASK-0005 the only new work is features.

Note `/api/v1/reference/whoami` will likely be absorbed or replaced by TASK-0003. Do not build
anything on it that would be expensive to unpick.

Watch out: this task and TASK-0002 may run concurrently. TASK-0002 regenerates the contract. If
the committed `contracts/openapi.json` hash changes under you mid-task, regenerate and re-run
the drift check before reporting — do not report against a stale document.
