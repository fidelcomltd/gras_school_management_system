# TASK-0013 — Decide and implement idempotency for retryable mutations

Owner: backend-dev
Depends on: —
Contract impact: none — Option B chosen 2026-09-04, nothing crosses the wire.
Status: done

## Goal

§6 requires that "mutating endpoints that can be retried accept an `Idempotency-Key`". Nothing in
the backend implements, documents, or deliberately declines it. Close that gap — either build the
mechanism or record an explicit, reasoned deviation with an owner and a trigger. What is not
acceptable is the current state: a §6 rule silently unmet.

## The finding (TASK-0001 finding B2, verified)

Zero occurrences of `Idempotency` in any `.cs`, `.csproj`, `.md` or `.ps1` under `backend/`, apart
from `dotnet ef migrations script --idempotent` in `README.md`. No middleware, no endpoint filter, no
`ASSUMPTIONS.md` entry, no `## Known drift` line.

Nothing is broken today — no product mutating endpoint exists — so this is **decide-now, not
fix-now**. It is carded as a blocker because `Endpoints/ReferenceEndpoints.cs` is the declared
copy-from template for every future module, and its doc comment (`:14-35`) enumerates "the same five
things every endpoint below demonstrates" without idempotency among them. Every future POST copied
from `MapCreateSampleRecord` inherits the gap, and retrofitting it across twenty endpoints is exactly
the expensive-later case TASK-0001 existed to surface.

Independent of §6, spec 9.8.2 requires idempotency keys on **pupil registration, pin generation,
promotion commit and result publication** — so the requirement arrives with Phase 2 regardless.

## Decision — Option B, human-approved 2026-09-04

**Defer the mechanism; land a binding record.** Not open for reinterpretation by the implementing
agent: do not build the filter.

Reasoning on record: no product mutating endpoint exists, so a mechanism built now has no real
caller to validate its hard parts against — key storage, request fingerprinting, and the
retention/purge rule §9.9 cares about. The risk that made this a blocker is not the missing
mechanism, it is `ReferenceEndpoints.cs` silently teaching its absence to every future POST copied
from it; that risk is closed by the documented TODO, which is cheap and immediate.

If while writing the record you conclude B is wrong, **stop and say so** — do not switch to A
mid-card. The choice had human sign-off and a change needs the same.
