# TASK-0034 — Make the generated OpenAPI document byte-reproducible across platforms

Owner: backend-dev
Depends on: none (TASK-0033 closed; this is independent of it)
Contract impact: additive/cosmetic — 93 `description` strings only, no endpoint, field, type,
status code or enum member changes. NOT breaking per CLAUDE.md §3. Hash moves.
Status: queued

## Goal

`./scripts/ci.ps1`'s gate 10 ("OpenAPI contract drift") passes on `ubuntu-latest`, and the
document promoted from a Windows workstation is byte-identical to the one a Linux runner
generates from the same commit.

## Root cause (already diagnosed — do not re-investigate)

Gate 10 compares `Get-FileHash` of `backend/artifacts/openapi/SchoolManagement.Api.json` against
`contracts/openapi.json`. Byte-exact, by design.

Roslyn writes the XML documentation files (`bin/**/SchoolManagement.*.xml`) using
`Environment.NewLine`, **not** the newline of the `.cs` source. Measured in this worktree:

- every backend `.cs` file is LF (`backend/.gitattributes` has `* text=auto eol=lf`)
- `SchoolManagement.Domain.xml` — 1937 CRLF, 0 bare LF
- `SchoolManagement.Application.xml` — 4096 CRLF, 0 bare LF

`Microsoft.Extensions.ApiDescription.Server` lifts those `<summary>` bodies into the OpenAPI
`description` fields, so a Windows-promoted document carries **93 escaped `\r\n` sequences
across 50 physical lines**. A Linux runner emits `\n` in the same places:

| | bytes | sha256 |
|---|---|---|
| committed (promoted on Windows) | 160883 | `73316bdb…` (= `CONTRACT.lock`) |
| what `ubuntu-latest` regenerates | 160697 | `9dca7f11…` |

50 differing lines, every one a `"description":` — which is exactly what the CI failure's
`Compare-Object … | Select-Object -First 40` dump showed. Both workflows are `runs-on:
ubuntu-latest`.

## Contract delta

No shape change. 93 `description` values lose an embedded carriage return. `contracts/openapi.json`
and `contracts/CONTRACT.lock` both move; expected new hash `9dca7f11ed2c4ed00cd444f2fe3d99af…`
(verify, do not trust this number — it is a prediction computed from the current document, not a
generator run).

## Approach

Normalise in `backend/scripts/generate-openapi.ps1`, on the **generated artefact itself**, before
anything hashes or copies it.

Placement matters and is the part most likely to be got wrong: gate 10 hashes
`backend/artifacts/openapi/SchoolManagement.Api.json`, not the promote output. Normalising only
inside the `-Promote` branch would leave a Windows workstation with a CRLF-bearing artefact and a
normalised contract, so gate 10 would then fail *locally* while passing in CI — the same bug with
the platforms swapped. Normalise once, on the artefact, on every run, `-Promote` or not.

Replace the 4-character JSON escape sequence `\r\n` with `\n` in the document's **text**, and any
remaining lone escaped `\r` with `\n` (0 occurrences today; defensive). Do not `ConvertFrom-Json`
and re-serialise — that reorders and reformats, moving far more bytes than the 93 this fixes.
Write back as UTF-8 **without BOM** and with LF file endings; the current document has no BOM and
4440 bare LF / 0 CRLF at file level, and that must not change either.

## Acceptance criteria

- [ ] `./scripts/generate-openapi.ps1` (no `-Promote`) produces an artefact with zero escaped
      `\r` sequences, on Windows.
- [ ] Run twice in a row without an intervening source change → byte-identical output both times
      (the cache-deletion logic at the top of the script already forces real regeneration; prove
      it still does).
- [ ] `./scripts/generate-openapi.ps1 -Promote` run, `contracts/openapi.json` and
      `contracts/CONTRACT.lock` updated, and the new hash recorded in the card log. Confirm the
      diff touches **only** `description` values — paste `git diff --stat` for `contracts/`.
- [ ] A test that fails if the normalisation regresses. `backend/scripts/tests/` already exists —
      put it there if that is where the script's own tests live, otherwise
      `SchoolManagement.ArchitectureTests` already reads this artefact (see ci.ps1 gate 4's
      comment) and is the natural home: assert no `description` in the document contains a
      carriage return. A fix to a cross-platform reproducibility bug with no test is not done.
- [ ] `./scripts/ci.ps1 -NoFailFast` green, gate 10 included, output pasted per §9. If the
      integration suite skips for want of `POSTGRES_TEST_CONNECTION`, say so explicitly — a
      skipped suite is not a passing suite (§13) — do not pass `-AllowSkipped` to make it quiet.

## Out of scope

- The **root `.gitattributes` gap** — there is no root `.gitattributes` and `core.autocrlf=true`,
  so `contracts/openapi.json` and `frontend/src/api/schema.d.ts` are unnormalised outside
  `backend/`. Both are LF in the worktree now only because a generator wrote them rather than a
  checkout. After a fresh clone on Windows they become CRLF and both drift gates fail locally
  while CI stays green. Real, latent, a different fix, orchestrator-owned, and an open question
  for the human — not this card.
- Regenerating `frontend/src/api/schema.d.ts`. The hash moves, so it may need it; but
  `openapi-typescript` already strips carriage returns (the committed `schema.d.ts` has 0 CR
  bytes), so the client output may well be unchanged. Do not touch `frontend/**` — the
  orchestrator checks the drift after this lands and cards it only if it actually moved.
- Weakening gate 10 to a canonicalised-JSON comparison instead of a hash. Rejected: it would
  leave the document itself non-reproducible and only hide it.

## Notes for the implementing agent

Read `backend/scripts/generate-openapi.ps1` fully first — the long comment above `$openApiCache`
explains why the cache file is deleted, and your change must not disturb that. `Set-StrictMode
-Version Latest` and `$ErrorActionPreference = 'Stop'` are already set at the top.

Be careful with PowerShell 5.1 here: `-replace` takes a **regex**, so a literal backslash needs
escaping, and `Out-File`/`Set-Content` do not default to BOM-less UTF-8 (root CLAUDE.md's shell
notes). Verify the written bytes rather than assuming — `Get-FileHash` before and after, and
check byte 0 is not `0xEF`.
