# TASK-0020 — Adopt §7's frontend structure, form and E2E mandates

Owner: frontend-dev
Depends on: —
Contract impact: none
Status: done

## Goal

The frontend adopts the three §7 mandates the 2026-08-03 scaffold deliberately skipped, so the
first real screen (TASK-0021) has an agreed home, a mandated form library and an E2E harness
waiting for it rather than inventing all three under deadline.

## The decision this implements

Open question 11, open since 2026-08-27, **resolved by the human on 2026-09-05: follow §7**, with
the proviso "as long as it will lead to a better file and codebase structure". Full text in
`.agent/decisions/2026-Q3.md` (2026-09-05). `frontend/HANDOFF.md`'s reasoning for the three
deviations is superseded — it was written before the product specification existed.

**The proviso is a guard against churn, not a per-case reopening.** It is already applied in the
scope below. Do not re-litigate it; if you think a specific move is churn, say so and stop.

## Acceptance criteria

- [ ] `src/features/` is the home for feature code, with the directory convention documented in
      `frontend/CONVENTIONS.md`: what goes in a feature folder, what does not, and what stays
      shared. `src/features/` is currently empty and reserved, so **nothing migrates into it here**
      — this card establishes the convention, TASK-0021 is its first user.
- [ ] `react-hook-form` and `@hookform/resolvers` (zod) added as dependencies, exact-pinned,
      lockfile committed. §8 justification: mandated by §7. **No form is built here** — TASK-0021
      builds the first one.
- [ ] Playwright added and running, with **one smoke spec that actually asserts something** about
      the app as it exists today, wired into a script and into `.github/workflows/frontend-ci.yml`.
      A harness with no passing spec is the "check that can pass without meaning anything" this
      project has spent three cards removing.
- [ ] The Playwright job's failure output is legible in CI (trace or screenshot on failure).
- [ ] `npm run verify` and `npm run check:api-drift` green, output pasted.
- [ ] `frontend/HANDOFF.md` updated: the three deviations recorded as superseded, dated, with a
      pointer to the decision. Do not delete its reasoning — it was correct for its time.

## Out of scope

- **Creating `src/shared/`.** Per the proviso: it appears when something genuinely shared needs
  it, and `src/components/`, `src/lib/` and `src/stores/` are NOT bulk-renamed into it. A rename
  across a working 130-test scaffold buys structure on paper and costs a large reviewable diff.
- **Deleting `src/screens/scaffold-status/`** and retiring `src/screens/`. That happens in
  TASK-0021 when a real screen replaces it, not before — deleting it here leaves no route at `/`.
- Any auth work. The bearer-to-cookie rewrite is TASK-0021 and depends on TASK-0003's contract.
- Any change under `src/api/` — it is generated.

## Notes for the implementing agent

Read `.agent/STATE.md` first and append last. §7 is `.agent/spec/frontend.md`; conventions are
`frontend/CONVENTIONS.md`. The router is React Router 7 in library mode
(`src/app/router/app-router.tsx` plus `paths.ts`), **not** file-based — directory structure has no
effect on URLs, so the `src/features/` convention is purely about code organisation.

This card touches no endpoint and changes no contract, so under §4.3 it may run in parallel with
TASK-0003. It is dispatched that way deliberately.
