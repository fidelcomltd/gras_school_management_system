## Goal

A Super Admin corrects a wrongly-issued registration number — usually a wrong admission year — by
typing the new number in full. The old number survives permanently as a lookup alias, so a parent
holding a pin slip printed with the old number still reaches the right child.

## Contract delta

- `POST /pupils/{id}/registration-number` — body `registrationNumber` (the new number, typed in
  full) and `reason` (**minimum 10 characters**). Privilege `pupil.regnumber.correct`, Super Admin
  only. 409 where the new number collides.

**Approved by the orchestrator 2026-09-15 as ADDITIVE** — a new path; no existing schema moves.
These four points are ORCHESTRATOR RULINGS, not your choices — implement them as written:

- **200 returns the existing `PupilDto`**, exactly as `POST /admissions/{id}/approve` does. Do NOT
  introduce a new response schema; the path count moves by one, the schema count by one (the new
  request command only).
- **409 error code `pupil.registration_number_duplicate`**, matching the repo's
  `<entity>.<field>_duplicate` convention (`arm.label_duplicate`, `role.name_duplicate`).
- Status set: `200, 401, 403, 404, 409, 422, 429` — the same set `approve` carries. `reason` under
  10 characters and a malformed number are **422**, not 409.
- `pupil.regnumber.correct` **already exists** at `Domain/Security/Privileges.cs:230` and is
  already excluded from every seeded non-Super-Admin role (`SeededRoles.cs:89,110`). Do not add it
  and do not widen any seeded role.

## Acceptance criteria

- [x] **The system does not generate the new number** (6.5.10) — the administrator types it. A
      handler that composes one from settings fails this card.
- [x] The new number must be unique against BOTH `pupil.registration_number` AND
      `pupil_reg_number_history`. Two tests, one per table — a check against only the live table is
      the obvious bug here.
- [x] The old number is written to `pupil_reg_number_history` with reason, actor and timestamp, and
      is never deleted. A test corrects twice and asserts BOTH old numbers remain as aliases.
- [x] `reason` under 10 characters is rejected.
- [x] The counter is NOT touched — a correction consumes no serial. Asserted against the counter row.
- [x] **Published result snapshots are not rewritten** (6.5.10). **VACUOUS, not proven** — no results
      module exists (only the documented `IResultSetArmLookup` seam), verified by the orchestrator
      rather than taken on report. Nothing was invented to satisfy it, which is what this criterion
      asked for. Drift filed 2026-09-15; the results card that first persists a snapshot owns the test.
- [x] Audited: the correction writes an audit event carrying old number, new number and reason.
