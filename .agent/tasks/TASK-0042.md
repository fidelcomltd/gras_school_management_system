## Goal

An administrator can run the school year end to end from the back office: create a session and its
three terms, open and close a term, and manage the class levels and sections that everything else
hangs off — including reordering the progression chain.

## Scope

**1. Sessions & terms** (`features/sessions/`)
- List sessions (`GET /sessions`, cursor-paginated) with state.
- Create a session (`POST /sessions`, `Idempotency-Key` REQUIRED) — creates all three terms server-side.
- Session detail (`GET /sessions/{id}`) showing its three terms.
- Edit session (`PATCH /sessions/{id}`) and term (`PATCH /terms/{id}`).
- Term transitions: `POST /terms/{id}/{open,close,reopen}`. Reopen needs a reason ≥ 10 chars and
  super-admin. **Precondition failures return a naming message — surface that message, never a
  generic "something went wrong".**

**2. Levels & sections** (`features/classes/`)
- Level list (`GET /levels`) in chain order, showing entry and graduating flags, `?status=all` toggle.
- Create level (`POST /levels`, `Idempotency-Key` REQUIRED) including the **insert-after** path —
  pick a predecessor and the server rewires the chain.
- Edit (`PATCH /levels/{id}`); changing status additionally needs `level.deactivate`.
- Delete (`DELETE /levels/{id}`) — surface the 409's named references.
- Reorder (`POST /levels/reorder`) — whole ordered array, atomic.
- Sections: list, create, rename (`/sections`, `/sections/{id}`), gated by `level.*`.
