## Goal

The office opens the admissions queue, sees every pending applicant with what is still missing from
each, and finishes the decision: approve one into a named arm — which issues the registration
number and turns the applicant into a real pupil — or decline it with a reason. Today the backend
can do both and no screen exists to reach either, so the feature is unshippable.

## Contract delta

**None.** Two operations already in the document become reachable:

- `ListAdmissionsQueue` — `GET /api/v1/admissions`, cursor-paginated. Rows carry
  `levelAppliedFor`, `dateApplicationReceived` and `missing`. Privilege `pupil.view`, SCHOOL-WIDE.
- `ApproveAdmission` — `POST /api/v1/admissions/{id}/approve`. **`Idempotency-Key` header is
  REQUIRED.** Privilege `pupil.admission.approve`. 409 when already decided.
- `DeclineAdmission` — `POST /api/v1/admissions/{id}/decline`, body `reason`. Same privilege.
- `ListArms` — `GET /api/v1/arms?sessionId=&levelId=` populates the arm selector.

## Notes for the implementing agent

**`frontend/src/features/arms/` is your template.** Same folder layout, same `api.ts` seam, same
`*-routes.tsx` with `RequirePrivilege`, same test style. Read it before writing anything.

**The generated request type will demand keys you think are optional.** `ApproveAdmissionCommand`
lists `assessmentResultRemarks` and `headOfSchoolName` in its `required` array while typing both
as nullable. Send them as explicit `null` when the user leaves them blank — omitting the key will
fail validation even though the value is optional in product terms. This is the single most likely
place this card goes wrong.

**`headOfSchoolName` left blank defaults server-side** from `settings.head_teacher_name`. Say so in
the field's help text rather than pre-filling it — the default is the backend's ruling to hold, and
pre-filling would silently freeze today's setting into the record.

**`missing` covers only what sections A and I can check today** (assessment result, declaration
signature). Steps 2 to 8 have no entity, so a gap there never appears in the array. Do not render
it as an exhaustive checklist — it is "what we can see is missing", and the copy should not
overclaim.

**Idempotency:** one key per dialog opening, held in component state, regenerated only when the
dialog is re-opened for a new decision. `crypto.randomUUID()`. Do not key off the pupil id.
