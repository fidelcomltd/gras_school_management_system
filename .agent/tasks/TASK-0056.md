## Goal

After any gate run, an agent can learn the result by reading one small file instead of holding a
multi-thousand-line log in its context window. `ci.ps1` already prints a `SUMMARY` block; nothing
persists it, so every reporting agent carries the whole run output to quote six lines of it.

This is a context-budget card, not a correctness card. It changes no product behaviour and must
not move the contract.

## Contract delta

None.

## Acceptance criteria

**Backend**

- [ ] `backend/scripts/ci.ps1` writes its existing `SUMMARY` block to
      `backend/artifacts/gate-summary.txt` (overwriting) in addition to printing it, on **every**
      exit path — pass, fail, and fail-fast abort. A run that dies at gate 3 must still leave a
      file saying so.
- [ ] The file's first line is a single verdict token: `PASS` or `FAIL`.
- [ ] The file names, for each gate that ran, the gate name and its outcome, plus the test totals
      (`total=`/`passed=`/`failed=`/`skipped=`) and the coverage line. Gates that did not run are
      listed as `SKIPPED-NOT-RUN` so a fail-fast abort is unambiguous.
- [ ] Every failing line from the failing gate is included in full. Nothing else from the log is.
- [ ] `backend/artifacts/gate-summary.txt` is gitignored.
- [ ] A test in `backend/scripts/tests/` proves the file is written on a FAILING run, not only a
      passing one. Per the standing lesson in STATE.md `## Decisions` (2026-09-05): a check that
      cannot be shown to fail is not a check — make the gate fail, watch the file appear with
      `FAIL`, then accept it.

**Frontend**

- [ ] `npm run verify` writes `frontend/artifacts/gate-summary.txt` in the same shape — verdict
      token first line, then per-step outcome and test totals.
- [ ] Written on failure as well as success. `npm run verify` must still exit non-zero on failure;
      writing the file must not swallow the exit code.
- [ ] `frontend/artifacts/` is gitignored.
- [ ] A vitest or script-level test proves the failing-run case.

**Both**

- [ ] `.agent/rules/gates.md` section 5 updated to say: read the summary file, quote it, never
      quote the log. (Orchestrator makes this edit at closure — do not edit `.agent/**` yourself.)

## Out of scope

- Changing which gates run, their order, their thresholds, or their fail-fast behaviour.
- Changing any gate's exit code.
- JSON output. Plain text is easier for an agent to quote verbatim into a report, and nothing is
  going to parse this programmatically.
- Merging `check:api-drift` or `test:e2e` into `verify` — they are deliberately separate.
- Touching CI workflow files. CI reads stdout and is unaffected; the orchestrator owns
  `.github/**` anyway.

## Notes for the implementing agent

- `ci.ps1` already builds the `SUMMARY` block — this is a capture-and-write, not a new report.
  Find where it composes that block and tee it; do not compose a second one that can drift from
  the first.
- The fail-fast path is the one that matters and the one easiest to miss. `ci.ps1` STOPS at the
  first failure unless `-NoFailFast`, so the early-exit path needs the write too. A `try/finally`
  around the gate loop is the obvious shape; confirm it survives the script's own
  `Push-Location`/`Pop-Location`.
- Watch the PowerShell 5.1 traps already recorded in `.agent/rules/gates.md` section 2 — no
  `2>&1`, and `Set-Content`/`Add-Content` default to ANSI, so pass `-Encoding utf8` explicitly or
  the file will be unreadable when it carries a non-ASCII character from a test name.
- `backend/artifacts/coverage/` already exists, so the artifacts directory convention is
  established; follow it rather than inventing a new location.
- You do NOT run the full gate to verify this (`.agent/rules/gates.md` section 1). Exercise
  `ci.ps1` through its own test suite in `backend/scripts/tests/`, which is where the existing
  `gate-summary.tests.ps1` lives.
- ⚠ That existing suite has a recorded weakness — STATE.md `## Known drift` 2026-09-05:
  `gate-summary.tests.ps1:101,:108` use `-match` substring assertions that pass even against a
  mangled path. **This card is that drift entry's trigger.** Fix those two assertions to in-process
  `-eq` while you are in the file, and say so in your report.
