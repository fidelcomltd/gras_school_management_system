## Goal

A class teacher records each pupil's attendance (times present) and writes the class teacher's remark for their arm and term.
The head teacher writes the head teacher's remark, with a fill-empty action for the whole arm. Both pick phrases from a list of
remark templates the school keeps and then edit the inserted text. This finishes the §6.7.7 inputs. The completeness gate and
the readiness grid come next, and they must be able to count everything this card stores.

## Rulings (human, 2026-09-19): all four went with the recommendation

- **L — Remark length 300**, per C.6, E.5 and F. §6.7.7's 240 is superseded, and this is recorded as drift.
- **A — Attendance stores `times_present` ONLY.** `timesAbsent` = `term.times_school_opened` − present is derived on read, and is
  null while opened is blank. Present may be entered before opened is set.
- **T — Two template lists by `kind`** (`ClassTeacher` | `HeadTeacher`). The class-teacher list needs `result.remark.classteacher` at
  ANY scope, and arm-scoped counts. The head-teacher list needs `result.remark.headteacher`.
- **H — The head teacher's remark is editable in Draft, Returned for Correction, Awaiting Approval and Approved.** It is 409 in
  Published and Withdrawn, and on a closed term.

## Contract delta (approved)

Every sheet mirrors `GetTraitRatings`/`SaveTraitRatings` exactly. Copy their error codes, `resultSet` block, `version`, CSRF, `Idempotency-Key`,
403-not-404 for an unknown arm, Q1-A null/omitted semantics, Q2-A omission of departed pupils, surname order, and PUT-returns-the-sheet.

1. `GET`/`PUT /api/v1/arms/{armId}/attendance?termId=`, as `GetAttendance`/`SaveAttendance`. GET needs `result.view` and PUT needs `result.attendance.enter`,
   both arm-scoped. The sheet adds `timesSchoolOpened: int|null`. Each row is `{pupilId, registrationNumber, displayName, timesPresent: int|null,
   timesAbsent: int|null}`. The PUT row is `{pupilId, timesPresent: int|null}`. The 422 `times_present_out_of_range` covers two cases:
   below 0, or above `timesSchoolOpened` when opened is set (200, the term field's own max, when it is blank).
2. `GET`/`PUT /api/v1/arms/{armId}/class-teacher-remarks?termId=`, as `GetClassTeacherRemarks`/`SaveClassTeacherRemarks`. GET needs `result.view` and PUT needs
   `result.remark.classteacher`, both arm-scoped. Each row is `{…identity, remark: string|null, writtenByName: string|null, writtenAt: date-time|null}`. The PUT row is
   `{pupilId, remark: string|null}`. Text is trimmed, and an empty or whitespace-only value clears the remark, like null. The 422 `remark_too_long` fires above 300 characters.
3. `GET`/`PUT /api/v1/arms/{armId}/head-teacher-remarks?termId=`, as `GetHeadTeacherRemarks`/`SaveHeadTeacherRemarks`. It has the same shape as 2. PUT needs
   `result.remark.headteacher`. The PUT body also takes an OPTIONAL `fillEmpty: string|null`. It sets that text for every listed pupil who
   has no remark, and never overwrites an existing one. `rows` may accompany it: rows apply first, then the fill. The fill is
   validated like a remark.
4. `GET /api/v1/remark-templates?kind=` (kind required), `POST /api/v1/remark-templates` `{kind, text}` returning 201 `RemarkTemplateDto`
   `{id, kind, text, createdAt}` with `Idempotency-Key`, and `DELETE /api/v1/remark-templates/{id}` returning 204. The list is in creation order. Text is trimmed,
   1–300 characters, else 422. A duplicate within a kind (trimmed, case-insensitive) is 409. An unknown id is 404 only for a caller holding
   the privilege for at least one kind; anyone else gets 403 first. It is a hard delete, because inserted text is copied, never referenced. The list ships empty.
5. The existing term update (`TermEndpoints.cs`, grep `UpdateTerm`) gains a 409. It refuses to set `times_school_opened` below the highest
   stored `times_present` for that term, so the derived absent can never go negative. This is a description-only change on an existing path.

Error-code strings: **copy the form the trait-rating handlers use; grep their constants, do not invent a prefix style.** The
orchestrator has got error-code prefixes wrong three times before.
