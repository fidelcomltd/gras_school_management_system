## Goal

An administrator signs in through the browser and lands in the back office. The provisional
bearer-token implementation is removed, not left dormant.

## The mechanism — not open for reinterpretation

**HttpOnly cookie session + CSRF token**, signed off by the human 2026-08-26 (CLAUDE.md §5,
`STATE.md ## Auth decision`). `frontend/src/lib/auth/` currently implements bearer-in-memory auth,
which is **known-wrong code carried deliberately** since 2026-08-26 awaiting this card.

The frontend holds no session token in JS at all — not in memory, not in `localStorage`. If any
part of this appears unworkable, stop and raise it. A carrier change needs human sign-off.

## Orchestrator rulings — 2026-09-06, binding, do not reinterpret

These close the gaps a dispatch would otherwise have to guess at. Each is a decision, not a
suggestion; if one looks wrong, stop and say so rather than working around it.

1. **AC-5 amended** (above) — approved delta §3a wins over the card's pre-delta phrasing.
2. **The CSRF token comes from the `GET /auth/csrf` RESPONSE BODY, never `document.cookie`.**
   The cookie is `HttpOnly=false` and is readable today only because dev shares the host
   `localhost`; the `__Host-` prefix forbids a `Domain` attribute, so on any deployment where the
   API is a different host the frontend cannot read it. Reading the cookie would work locally and
   break in production — the worst failure shape available.
3. **The CSRF token rotates on sign-in and on password change** (`AuthEndpoints.cs`). Re-fetch at
   those points, and on a `403` whose `errorCode` is `csrf.missing`/`csrf.invalid` re-fetch once
   and retry that request once. That single CSRF retry is the ONLY retry in the layer — it is not
   an auth retry and must not grow into one.
4. **Proactive keepalive schedule:** derive it from the backend-reported `sessionExpiresAt` minus
   the already-configured `VITE_AUTH_EXPIRY_LEEWAY_SECONDS`, re-armed from EVERY
   `AuthSessionResponse` (sign-in, `me`, `refresh`, `password`), and clamped so it never fires
   past `sessionAbsoluteExpiresAt` — at the absolute cap there is nothing to extend, so go to
   sign-in rather than call `/refresh`. The leeway is a clock-skew allowance, not an assumed
   duration: keeping it satisfies the no-hardcoded-duration criterion; inventing a 30-minute or
   8-hour literal violates it.
5. **Route shape:** `paths.signIn` = `/sign-in`. `/` becomes a PROTECTED landing rendering
   `staffName` from `GET /auth/me` plus a sign-out control — the minimum that lets the logout
   criterion and the replacement smoke assertions test something real. Unauthenticated `/`
   redirects to `paths.signIn`. No nav, no dashboard, no widgets: that is TASK-0027 onward.
6. **`mustChangePassword` is OUT OF SCOPE to implement** (no change-password screen in this card)
   but MUST NOT deadlock. `me` is exempt from the gate (delta §2a) while `refresh` is not, so a
   flagged account renders a plain "you must change your password before continuing" state on the
   landing and does NOT schedule the keepalive. Record it in `## Known drift` naming the
   follow-up owner; do not build the screen here.
7. **Playwright runs against `vite preview` with NO backend** (`playwright.config.ts`). Stub
   `**/api/v1/auth/**` with `page.route`, including `Set-Cookie` on the sign-in response. Do NOT
   add a backend or database dependency to the frontend CI job.
8. **The live proof for the CORS/cookie criterion** is a running API started WITHOUT writing
   anything under `backend/**` — environment overrides only: `ASPNETCORE_ENVIRONMENT=Development`,
   `Database__ConnectionString` (from `$HOME/.gras/pg-test.txt`),
   `Cors__AllowedOrigins__0=http://localhost:5173`, `Cors__AllowedOrigins__1=http://localhost:4173`,
   `Authentication__Mode=CookieSession`. Then `curl -i` `GET /api/v1/auth/csrf` and an `OPTIONS`
   preflight carrying `Origin: http://localhost:5173`, and paste the real `Set-Cookie` and
   `Access-Control-Allow-*` lines. **If the API cannot be brought up that way, STOP and report it**
   — do not substitute reading the config, which is the exact thing the criterion forbids.
