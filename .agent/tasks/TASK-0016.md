# TASK-0016 — Make the gate suites fail fast and fail honestly

Owner: backend-dev, then frontend-dev (sequenced, disjoint files, no contract impact)
Depends on: none
Contract impact: none
Status: queued

## Goal

A gate run tells the truth as cheaply as possible. Two defects today: the suites run expensive
checks before cheap ones, so an agent that broke a typecheck waits for a database round trip to
find out; and `ci.ps1`'s coverage gate recognises skipped tests but not **failed** ones, so it
has printed `PASS` on a run with failures. The second one has already cost this project real
money — TASK-0002 was reported done twice on runs whose integration suite silently skipped, each
false close costing a full re-dispatch of a Sonnet session.

## Contract delta

None. No file under `backend/src/**`, `frontend/src/**` or `contracts/**` changes.

## Acceptance criteria

- [ ] `backend/scripts/ci.ps1` runs its gates cheapest-first and stops at the first failure:
      restore → format → build `-warnaserror` → unit tests → integration tests → coverage floor
      → vulnerable-package scan → gitleaks → OpenAPI drift. A `-NoFailFast` switch preserves the
      current run-everything behaviour for CI, which wants the full picture.
- [ ] `ci.ps1` exits non-zero when the test run reports `Failed > 0`, proven by a test that feeds
      the parser a fixture summary line with failures and asserts a non-zero exit. This closes
      the `## Known drift` entry of 2026-08-27.
- [ ] `ci.ps1` exits non-zero when `Skipped > 0` unless `-AllowSkipped` is passed explicitly, and
      prints which suite skipped. A skipped suite is not a passing suite (CLAUDE.md §13).
- [ ] The final summary is a fixed block: one line per gate with its verdict, plus the test and
      coverage numbers. An agent can paste that block and nothing else and have satisfied §9.
- [ ] `frontend/package.json` gains a `verify` ordering with the same property — typecheck → lint
      → test → build, stopping at the first failure — and `check:api-drift` stays separate.
- [ ] Both suites' happy path and both failure modes are exercised by a test, not by inspection.

## Out of scope

- Changing any gate's threshold, including the coverage floor.
- Adding or removing a gate. `Docker.DotNet.Enhanced` verification stays with its drift entry.
- CI workflow restructuring beyond passing `-NoFailFast`.
- Anything under `backend/src/**` or `frontend/src/**`.

## Notes for the implementing agent

Read `backend/scripts/ci.ps1` first and find the existing summary-parsing code — the coverage
gate already parses `Skipped`, so the failure case is an extension of code that exists, not a new
parser. `.agent/drift/2026-Q3.md`, entry dated 2026-08-27, records exactly what it printed on the
run where it got this wrong; reproduce that run as your fixture.

The `-LiteralPath` fix noted in `decisions/2026-Q3.md` touched this same gate — read that entry
before editing, so the two fixes do not collide.

Do not treat this as licence to tidy `ci.ps1` generally. It is a working script with eight gates
wired into two CI workflows; the diff should be legible as "ordering, plus two exit conditions,
plus a summary block".
