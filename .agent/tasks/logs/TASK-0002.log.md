  **Judgement call requested on `EverySchema_HasAnExample`'s test placement: agree, it should be
  an architecture test (or an architecture-test-project equivalent), not an integration test.**
  It asserts a static property of the generated OpenAPI document — every schema has an `example`
  — and needs no running host, no database, and no `WebApplicationFactory`; the document itself
  is build output that `generate-openapi.ps1` already produces (and `ci.ps1`'s drift gate already
  regenerates) with zero live infrastructure. Fetching it over HTTP from a live host in
  `IntegrationTests` couples a pure document-shape check to database availability for no benefit,
  and that coupling is the entire reason this defect shipped in a committed contract: the check
  that would have caught it skipped silently instead of running. The same argument applies to its
  neighbours in `OpenApiContractTests` — `EverySchema_HasADescription`,
  `EveryOperation_HasASummaryDescriptionAndOperationId`, `EveryOperation_DocumentsItsErrorResponses`,
  `Document_HasApiLevelDocumentation`, `EveryDateTimeProperty_HasAnExample`,
  `Document_DescribesTheReferenceEndpoints`, `Document_UsesConcreteVersionSegmentsNotRouteTemplates`
  — none of them touch the database or exercise a request handler; they all read the document.
