  **Path templating**: a `pathParams` field on the trailing options argument, substituted into
  `{name}` segments at call time (`buildPath`), type-driven from
  `operations[...]["parameters"]["path"]` via `PathParamsOf<Op>`. The whole options argument
  becomes REQUIRED (not just the field) exactly when an operation declares a path parameter —
  proven with `@ts-expect-error` on `apiGet`/`apiPatch`/`apiDelete` calls against
  `/admins/{id}` and `/admins/{id}/sessions` omitting it, both with the options argument absent
  and present-but-empty.

  a generic headers bag), required exactly on `POST /admins` (proven `@ts-expect-error` when
  omitted) and optional on `PATCH /admins/{id}`, `POST /admins/{id}/status`,
  `POST /admins/{id}/password-reset` and `PATCH /settings/identity` (derived generically from
  the header parameter's own required/optional-ness in the schema, not hardcoded per path).
  **`X-CSRF-Token` deliberately has no field anywhere in the typed surface** — `CallerOptions`
  is `Omit<RequestOptions, 'headers'>`, so the only header a caller can ever set through
  `client.ts` is `Idempotency-Key`; CSRF stays exactly where it was; `http-client.ts`'s request
  interceptor (unmodified, still lines ~83/136) injects it on every mutating request regardless
  of what the schema's header parameter says is "required".
