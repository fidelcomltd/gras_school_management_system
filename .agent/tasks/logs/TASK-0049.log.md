- 2026-09-09 **REOPENED by orchestrator on one point. Everything above stands; do not redo it.**
  `GET /api/v1/audit-events/export`'s **200 response declares no `content` in the promoted
  contract** — it is exactly `{"description": "OK"}`, with no `text/csv` media type and no schema.
  Runtime is correct and tested (`Export_ReturnsCsvWithTheThirteenColumnsAndTheMatchingRows`
  asserts `ContentType.MediaType == "text/csv"`), and this is NOT a generator convention: the same
  operation's 401/403/422/429 all carry `content`, and `ListAuditEvents`' own 200 carries
  `content."application/json"`. So the `.Produces(StatusCodes.Status200OK, contentType: "text/csv")`
  metadata is being dropped on the way into the document.

  **Why this blocks closure rather than becoming a follow-up card.** §3: `openapi.json` is the
  single source of truth for every byte crossing the HTTP boundary. §1: a frontend agent needing a
  response shape reads the contract — "never the backend source, and never an assumption". The
  frontend regeneration card that follows this one would therefore have no sanctioned way to learn
  that this endpoint returns CSV, and `openapi-typescript` will generate a content-less 200. The
  cheapest place to fix a contract hole is the card that owns the endpoint.

  Not breaking: the document currently says *nothing* about this body, and no generated client
  consumes it yet, so declaring it is additive.


- 2026-09-09 **backend-dev: reopened point fixed.** Root cause confirmed: in
  `backend/src/SchoolManagement.Api/Endpoints/AuditEventEndpoints.cs`, `MapExport` declared
  `.Produces(StatusCodes.Status200OK, contentType: "text/csv")` — the non-generic overload, which
  supplies no response `Type`. The generator silently omits `content` for an untyped response even
  when a `contentType` is passed, which is why 401/403/422/429 (all `ProducesProblem`, which does
  supply a type) and `ListAuditEvents`' 200 (`Produces<CursorPage<AuditEventDto>>`) all carried
  `content` while this one didn't.

  `.Produces<string>(StatusCodes.Status200OK, contentType: "text/csv")`. Considered an
  `IOpenApiOperationTransformer` (the codebase already has two: `CsrfHeaderOperationTransformer`,
  `IdempotencyHeaderOperationTransformer`) but the generic `Produces<T>` overload alone was
  sufficient — confirmed by regenerating and inspecting the document before writing any transformer.
  No shared file touched; nothing else in the document changed as a result (see below).
