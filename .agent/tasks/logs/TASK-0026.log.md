  **Fix 1 — CA1873.** Reproduced locally by forcing `-p:AnalysisLevel=10.0-All` on this same SDK
  (no second SDK needed): this surfaced the card's cited site
  (`RequestLoggingBehavior.cs(84,21)`, `RequestCancelled`) AND three more the card didn't
  mention — `RequestLoggingBehavior.cs(56-60)` (`RequestFailed`), and, once every project built at
  the real pin, `GlobalExceptionHandler.cs` ×3 and `EndpointModuleExtensions.cs` ×1. All six fixed
  by guarding with `logger.IsEnabled(...)` and hoisting the computed argument to a local INSIDE the
  guard (the pattern the success path already used) — confirmed clean at the forced level, then
  again under the real committed pin and under `ci.ps1`.

  **Fix 2 — analyzer version pin.** `AnalysisLevel` → `10.0-All` (Directory.Build.props) +
  `Microsoft.CodeAnalysis.NetAnalyzers` `PackageVersion` `10.0.100` (Directory.Packages.props). A
  bare `PackageReference` to that package does NOT supersede the SDK-bundled analyzer on this SDK —
  verified via `dotnet build -v:diag`, grepping the literal `csc.exe /analyzer:` switches: only SDK
  paths appeared. New `backend/Directory.Build.targets` removes the SDK's implicit `Analyzer` items
  by metadata match and re-adds the pinned package's DLLs in a `Target BeforeTargets="CoreCompile"`
  (a static ItemGroup can't batch-Remove by metadata — MSB4191). Re-verified via the same grep:
  SDK paths gone, pinned paths present, full solution builds 0 warnings/0 errors.

  **Fix 3 — test bridge.** `TestingPlatformDotnetTestSupport=false` declared explicitly in
  `backend/tests/Directory.Build.props` (its default lives in `Microsoft.Testing.Platform.MSBuild`,
  a transitive, unpinned-floor dependency of xunit.v3). Verified: `dotnet test` with `ci.ps1`'s
  exact arguments produces classic VSTest output (`.trx` + coverlet) both before and after — this
  machine already defaulted to `false`, so CI's failure with a newer resolved package version could
  not be reproduced, only argued from the mechanism. Attempted, then reverted: pinning
  `Microsoft.Testing.Platform.MSBuild`'s own version via CPM broke restore (`NETSDK1013`, empty
  `TargetFramework` — its `buildMultiTargeting` assets import unconditionally once centrally
  pinned). Recorded as new drift, not closed.
