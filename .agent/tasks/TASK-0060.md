## Goal

Spec 4.2.1's privilege check is "… **in the session the target belongs to**". Today
`PrivilegeDecision` ignores `PrivilegeGrant.SessionId` entirely, so a grant scoped to one academic
session authorises the same action against a target in another. This card makes the session
dimension actually bite.

## Contract delta

None expected. See header.

## Why it is still open after TASK-0059

TASK-0059 implemented `IPupilArmOfRecordLookup` for real, so a pupil's arm — and through the arm,
its session — is now resolvable. That removed the reason the TODO originally gave. It did **not**
resolve the concern, because pupil routes never declare `ScopeParameterKind.Pupil` through
`ScopeResolver`; they use the handler-level `PupilAccessGuard` instead. So the `SessionId`
dimension is still never exercised by a real caller.

This is cross-cutting — it spans every scoped route, not just pupils — which is why it was kept out
of TASK-0059 rather than bolted on.
