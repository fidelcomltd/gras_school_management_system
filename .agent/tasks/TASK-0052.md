## Card text corrections

Recorded by the orchestrator on closure, 2026-09-09. Each was found by `frontend-dev` at execution
time, flagged rather than silently followed, and then **independently re-verified by the
orchestrator against `contracts/openapi.json` with `jq`** before being accepted. None of them
reached shipped code — this card is client-seam-only, so nothing downstream inherited a wrong
assumption. All four were card-authoring errors, not contract or implementation faults.

1. **`GetRegNumberPreview`'s `separator`/`serialWidth` are REQUIRED, not optional.** The contract
   marks both `"required": true`. Verified: `jq '.paths["/api/v1/settings/reg-number/preview"]
   .get.parameters | map({name,required})'` → both `true`.
2. **`FindPupilDuplicates` declares THREE query parameters, not four, and the date one is
   `dateOfBirth`, not `dob`.** There is no `contactPhone` parameter; contact matching waits on a
   `pupil_contact` table and belongs to a later card. Verified: `jq
   '.paths["/api/v1/pupils/duplicates"].get.parameters | map({name,required})'` → `surname`,
   `firstName`, `dateOfBirth`, all required.
3. **`YearSource` is not an enum in this contract.** `SettingsRegNumberGroupDto.yearSource`
   generates as plain `string` with a fixed `AdmissionYear` example and no schema behind it, so
   there is no enum to prove §8 tolerance of. Verified: `jq '.components.schemas | keys'` contains
   `PupilSex`, `PupilStatus`, `RegNumberSerialReset` and **no** `YearSource`. The agent correctly
   wrote no test for this bullet rather than fabricating one — that was the right call and the
   card's own "do not fabricate a proof" instruction working as intended.
4. **This move DOES supply a new omitted-required-header instance.** The card assumed the
   reg-number `PATCH`es were the only candidates and, since `Idempotency-Key` is optional on both,
   that the direction might have no new instance. But `CreatePupil` (`POST /api/v1/pupils`) —
   part of the same move — requires it. Verified: `jq '.paths["/api/v1/pupils"].post.parameters'`
   → `Idempotency-Key`, `"required": true`. Proven there; no older operation reused.

Minor, no AC affected: this card writes `PupilStatus`' members lowercase
(`pending`/`active`/…). The contract declares them PascalCase
(`Pending`/`Active`/`Transferred`/`Withdrawn`/`Graduated`), which is what the tests use.

**For the eighth run of this card:** the recurring body is sound and the traps it warns about keep
paying off — the inline-array/no-example trap was hit and cleanly handled for the third card
running. What failed here was writing *specific contract facts* into acceptance criteria from the
backend card's prose instead of from the promoted document. Derive per-parameter required/optional
claims and enum membership from `contracts/openapi.json` with `jq` at card-authoring time, or
state the shape as an open question and let the implementing agent establish it.
