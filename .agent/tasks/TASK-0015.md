## Acceptance criteria

- [x] **`/health/ready` must not be an unauthenticated, unthrottled database round trip.**
      `Endpoints/HealthEndpoints.cs:57-65`. Health checks are mapped on `app`, not the rate-limited
      `versionedApi` group (`Program.cs:261-264`), and no global limiter exists (`Program.cs:167-213`
      registers named policies only) — so an anonymous caller can drive one DB query per request
      (`AddDbContextCheck`, `InfrastructureDependencyInjection.cs:114`). §6: "Rate limiting middleware
      on public endpoints."
      The tension the file itself documents is real: throttling a probe causes false unhealthy
      signals and fleet restarts. Resolve it with a dedicated generous policy sized for real probe
      intervals, NOT by reusing an endpoint policy, and NOT by removing the DB check from `ready` —
      readiness genuinely means the database is reachable. State the numbers you chose and the probe
      interval they assume. If you conclude this belongs at the ingress rather than the app, say so
      with reasoning and record it as drift instead of implementing something worse.
- [x] **Move the persistence-error translation behind an Application port.**
      `Http/GlobalExceptionHandler.cs:3` imports `SchoolManagement.Infrastructure.Persistence` and
      calls `PersistenceErrors.TryTranslate(exception)` inside the HTTP pipeline. The Api project's
      own `.csproj` header scopes its Infrastructure reference to "register services in DI
      (`Program.cs`)"; this is outside that scope, and it puts a persistence concern in the Api layer.
      §6 layering. Introduce an Application abstraction implemented by `PersistenceErrors` and inject
      it.
- [x] **Add the missing architecture test that would have caught it.** `DependencyDirectionTests`
      asserts that `Application` does not depend on Infrastructure or Api, and that nothing depends on
      Api — but nothing constrains **Api -> Infrastructure**. That is the one layering rule in the repo
      that is documented rather than enforced, which is why the above slipped in. Add the rule, with
      whatever narrow exemption `Program.cs` genuinely needs for DI registration.
- [x] **The relocated document tests must not pass against a stale artefact.**
      `tests/SchoolManagement.ArchitectureTests/OpenApiDocument.cs:38-44` checks only `File.Exists`.
      Inside `ci.ps1` that is sound — a dedicated gate regenerates immediately before `dotnet test`.
      Outside it, a bare `dotnet test` asserts all eight document properties against whatever JSON is
      on disk, which may predate the current `src`. **Missing fails loudly; stale passes silently** —
      the same defect family as TASK-0010, where a target reported success over a document it had not
      written. Compare the artefact against the newest file under `src/SchoolManagement.Api` by
      timestamp, or hash-check it, and fail with a message as actionable as the existing missing-file
      one.
- [x] `./backend/scripts/ci.ps1` green with the integration suite RUNNING (`Skipped: 0`) — use
      `backend/scripts/local-env.ps1`. A skipping run is not a pass; the coverage floor also stands
      down when anything skips, so a skipping run degrades two gates while printing green.
- [x] Contract hash unchanged at `b287da03`. Nothing here should move the contract; if it does, that
      is a defect — stop and report.
