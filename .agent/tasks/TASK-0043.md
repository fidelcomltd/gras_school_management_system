## Goal

An administrator can manage who else has access: create and edit admin accounts, suspend and
reactivate them, reset a password, revoke sessions, and define the roles and privileges those
accounts carry.

## Scope

**1. Admin accounts** (`features/admins/`)
- List (`GET /admins`, cursor-paginated), detail (`GET /admins/{id}`).
- Create (`POST /admins`, `Idempotency-Key` REQUIRED) — surfaces the generated temporary password
  **once**, with a clear "this will not be shown again" affordance.
- Edit (`PATCH /admins/{id}`), status change (`PATCH /admins/{id}/status`) for suspend/reactivate.
- Password reset (`POST /admins/{id}/password-reset`) — same one-time-reveal treatment.
- Revoke sessions (`DELETE /admins/{id}/sessions`).

**2. Roles** (`features/roles/`)
- List (`GET /roles`), detail (`GET /roles/{id}`), create (`POST /roles`, `Idempotency-Key`
  REQUIRED), edit (`PATCH /roles/{id}`), delete (`DELETE /roles/{id}`).
- Privilege picker built from `GET /privileges` — the 93-row register, grouped by its module
  field. It is authenticated-only and needs no privilege of its own.
- System roles cannot be deleted; surface the 409's message verbatim.

## Notes for the implementing agent

`features/sessions/` and `features/classes/` (TASK-0042) are the current reference feature folders.
Reuse `src/shared/forms/field-message.ts`, `require-privilege.tsx` and `authenticated-shell.tsx`.

**The temporary password deserves real care.** The backend redacts it from stored idempotency rows
(TASK-0027), and the secret-scan gate has fired twice in this repo on example values of it. Keep it
out of React Query's cache, out of any state that outlives the dialog, and out of error paths.

Privilege codes are a fixed compile-time register — do not hardcode a copy of the 93 rows in the
frontend. Read them from `GET /privileges`.
