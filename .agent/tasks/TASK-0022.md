# TASK-0022 — Make the gate self-tests run on the CI host, not just on Windows

Owner: backend-dev
Depends on: none (blocks every card — CI is red on PR #9)
Contract impact: none
Status: done — closed 2026-09-05 (reconciled 2026-09-14)

## Goal

`backend-ci` completes on `ubuntu-latest`. The gate-summary self-test — the thing that guards the
guard — executes under `pwsh` on Linux instead of dying on a missing `powershell.exe`, and the
parser it tests derives suite names correctly regardless of which OS wrote the `.trx`.

## The failure

PR #9, job `quality-gates`, step **"Self-test the gate-summary trx parser"** fails in 7s. Chain:

1. `scripts/tests/gate-summary.tests.ps1:79` runs `& powershell.exe @arguments`.
2. CI runs it with `shell: pwsh` on `ubuntu-latest`. `powershell.exe` does not exist there.
3. `$ErrorActionPreference = 'Stop'` (line 36) turns the first call (line 87) into a terminating error.
4. Step exits non-zero → **"Run all quality gates" is skipped** → no `.trx` is written.
5. "Assert the integration tests were not skipped" (`if: always()`) reports
   `No test results file found; cannot verify the integration tests ran.` and exits 1.

Steps 4 and 5 are correct behaviour. There is ONE defect, and it is step 1.

**This is the TASK-0011 family**: a gate that had never executed in its real environment was
reporting PASS. The script header even records the reason — the authoring machine has no `pwsh`,
so `powershell.exe` was hardcoded and the Linux path was never exercised.

## Acceptance criteria

- [ ] The self-test invokes **the PowerShell host it is itself running under**, not a hardcoded
      `powershell.exe`. It must work under `pwsh` on Linux AND under Windows PowerShell 5.1 on the
      dev machine — the child-process design (asserting on a real exit code) is deliberate and
      **stays**; only the executable resolution changes.
      Note `$IsCoreCLR` / `$IsWindows` are UNDEFINED in 5.1 and `Set-StrictMode -Version Latest`
      makes referencing them throw. `$PSVersionTable.PSEdition` and `(Get-Process -Id $PID).Path`
      are safe in both.
- [ ] **Verify the second defect before claiming the first is fixed.** `lib/gate-summary.ps1:80`
      uses `[System.IO.Path]::GetFileNameWithoutExtension($storage)`, and every fixture `.trx`
      carries a Windows `storage` path (`c:\users\hp\...\schoolmanagement.integrationtests.dll`).
      On Unix, .NET treats only `/` as a separator, so this likely returns the whole mangled path
      and the assertion at `gate-summary.tests.ps1:130` fails. Confirm by running, then fix
      `Get-SuiteName` to split on BOTH `/` and `\` explicitly rather than delegating to
      `System.IO.Path`. A real `.trx` written on Linux CI has Unix paths and one written on a dev
      Windows box has Windows paths — the parser must handle both **on either host**.
- [ ] A fixture covers the Unix-`storage` shape as well as the Windows one. Per the standing
      lesson, fixtures must reproduce the real artefact's shape — and CI's real artefact is the
      one shape currently untested.
- [ ] `scripts/tests/local-env.tests.ps1:107` carries the identical `powershell.exe` hardcode.
      It is not wired into the workflow, so it is latent, not failing. Fix it the same way.
- [ ] **Prove the self-test can still fail.** Break `gate-summary.ps1` deliberately, watch the
      self-test go red, restore it. A check that cannot be shown to fail is not a check
      (standing lesson, 2026-09-04). Paste both outputs.
- [ ] Say explicitly whether `local-env.tests.ps1` should be wired into the workflow, or argue why
      not. Do not wire it in silently — that is `.github/**`, which the orchestrator owns.
- [ ] `./backend/scripts/ci.ps1` green locally with `Skipped: 0`, `SUMMARY` block pasted (§9).
