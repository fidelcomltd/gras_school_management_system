## Goal

A pending admission carries the paper form's sections A, I and J, so the office can record what
class was applied for, when the pupil was admitted, whether an assessment is required, and that the
declaration was signed — and so the admissions queue can show the office what each record is still
missing. **This card issues no registration number and approves nothing**; it builds the record
TASK-0051's approval reads.

## Contract delta

- `POST /pupils` — request gains a REQUIRED `admission` object: `sessionId` (optional, defaults to
  the active session), `dateApplicationReceived` (optional), `dateAdmitted` (optional, defaults
  today), `classAdmittedInto` (required), `admissionType` (`new` | `returning`),
  `admissionTypeNote` (optional), `assessmentRequired` (required boolean). Response gains the same
  object. 6.5.9 is the field table; do not invent names outside it.
- `PATCH /admissions/{id}` — NEW. Partial payload over sections A, I and J: every field above plus
  `assessmentResultRemarks`, `assignedClassTeacher`, `declarationName`, `declarationSigned`,
  `declarationDate`, `headOfSchoolConfirmed`, `headOfSchoolName`. **A half-finished step still
  saves** (6.5.11) — absent fields are untouched, explicit `null` clears a nullable field.
  Privilege `pupil.update`. 404 for a non-pending pupil.
- `GET /admissions` — each row gains `levelAppliedFor`, `dateApplicationReceived`, and
  `missing`: the list of blocking items 6.5.11 step 9 names, restricted to what exists today (see
  Out of scope). `lastStepReached` is NOT in this card.
- `approvedBy` / `approvedAt` are written by TASK-0051 only. They are readable here, never writable.

## Acceptance criteria

- [ ] `AdmissionRecord` entity with 6.5.9's field table, one row per pupil, created in the SAME
      transaction as the pupil by `CreatePupilHandler` — a pupil with no admission record is a
      state the code cannot produce.
- [ ] `assessmentResultRemarks` is required only where `assessmentRequired` is true AND approval is
      being attempted (6.5.9). It is NOT required to save. A test proves both halves.
- [ ] `declarationDate` is required where `declarationSigned` is true, and rejected otherwise.
- [ ] `classAdmittedInto` must be an existing, non-archived `ClassLevel`; a level with no arm in
      the session is ACCEPTED here and blocks only at approval (6.5.11), which is TASK-0051's job.
      A test proves it saves.
- [ ] `dateAdmitted` and `dateApplicationReceived` are rejected in the future (6.5.9).
- [ ] `PATCH /admissions/{id}` saves a partial payload without clearing absent fields, proven by a
      test that writes two disjoint partial payloads and asserts both survive.
- [ ] The pending-exclusion invariant is untouched: `GET /pupils` still omits these records and
      `GET /admissions` still shows them. Re-assert, do not re-implement.
- [ ] `openapi.json` regenerated; the diff is additive only, and `contract-guardian` agrees.
