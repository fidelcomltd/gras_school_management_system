## Goal

The school can edit its grading scale and its assessment structure, both seeded to what the
school's own result sheets print, both versioned into `config_version`, with every validation rule
enforced server-side. This is the deepest unbuilt dependency in the product: the computation
engine (TASK-0071) cannot resolve a grade or a CA total without it.

## Three traps, each one a stale number in the spec

§6.2.13 is an amendment that **replaces** seed data stated earlier in the same file. The earlier
text was not deleted. If you read §6.2.5 or §6.2.6 alone you will build the wrong thing.

| Where | The stale text says | Build this instead |
|---|---|---|
| §6.2.5 seeded scale table | Six bands, A 80-100 … F 0-39 | **Nine bands** from §6.2.13: A+ 90-100, A 85-89, B 75-84, B- 70-74, C+ 60-69, C 50-59, D 40-49, E 20-39, F 0-19 |
| §6.2.5 `grade_letter` field | `String 2` | **String 3.** §6.2.13 widens it to hold `A+` and `B-` |
| §6.2.6 seeded structure | First CA 15, Second CA 15, Assignment 10, Exam 60 | **1st CA 20, 2nd CA 20, Exam 60.** No assignment component |

Also: §6.2.5's "Reset to defaults restores the six seeded bands" now restores **nine**.

## The durability requirement — read this before you design the tables

§6.2.13 carries a directive from the school: reintroducing an assignment component at another
installation must be a configuration change, never a code change. That constrains this card more
than any validation rule does.

**Nothing may assume a component count.** Concretely, and these are gate-able:

- The continuous-assessment total is computed as the sum of every component where
  `is_examination` is false. **The literal `40` must not appear in code, in a column heading, in a
  validation message, or in a test fixture.** A grep for it in your diff should return nothing.
- Column headings are composed from the component's own `name`/`short_label` and `max_mark`.
- Any payload returning components returns them as an **ordered array**, never as named fields
  like `first_ca` / `second_ca`. A client reading those by name breaks when a school adds a column.
- Two seed profiles exist, `gras_default` (20/20/60) and `with_assignment` (15/15/10/60). A profile
  writes rows and is not stored on the school; nothing may later branch on which was chosen.
