# TASK-0007 — Clear the SSH.NET High advisory blocking the vulnerable-dependency gate

Owner: backend-dev
Depends on: —
Contract impact: none
Status: queued

## Goal

`./backend/scripts/ci.ps1`'s "Vulnerable dependencies" gate is red and has been since before
TASK-0002. Until it is green, CLAUDE.md §9 is not satisfied and every card that follows closes
against a known-failing gate — which is how a red gate stops being information and becomes
background noise.

## The finding

```
Project `SchoolManagement.IntegrationTests` has the following vulnerable packages
   > SSH.NET   2025.1.0   High   https://github.com/advisories/GHSA-q939-rpr3-3284
```

Verified by the orchestrator on 2026-08-26:

- **Confined to `SchoolManagement.IntegrationTests`.** Every other project — Api, Application,
  Domain, Infrastructure, ArchitectureTests, UnitTests — reports no vulnerable packages. It is a
  test-only dependency and **never ships to production**.
- Reached transitively: `Testcontainers.PostgreSql 4.13.0` → `Docker.DotNet` → `SSH.NET`.
- The vulnerable surface is Docker.DotNet's SSH transport for **remote** Docker hosts. This
  project's fixture only ever talks to a local daemon or an externally supplied
  `POSTGRES_TEST_CONNECTION`, so the path is not one we exercise.
- **Pre-existing, not introduced by TASK-0002** — confirmed: no `.csproj` or
  `Directory.Packages.props` change in that card, package graph unchanged.
- `Testcontainers.PostgreSql 4.14.0` exists. It has not been tried.

Background written up by the implementing agent in `backend/docs/ASSUMPTIONS.md` §3.8, which
deliberately stopped short of accepting the risk unilaterally. That was the right call.

## Acceptance criteria

Work the options in order and stop at the first that succeeds.

- [ ] **Option 1 — bump.** Raise `Testcontainers.PostgreSql` 4.13.0 → 4.14.0 in
      `Directory.Packages.props`. Re-run `dotnet list package --vulnerable --include-transitive`.
      If the advisory clears, this card is done.
- [ ] **Option 2 — pin transitively.** If 4.14.0 still resolves a vulnerable `SSH.NET`, pin
      `SSH.NET` to a patched version via central transitive pinning, the same mechanism
      `backend/docs/ASSUMPTIONS.md` §2.11 already uses for `Microsoft.OpenApi`. Verify
      Testcontainers still functions — a pin that breaks the harness is not a fix.
- [ ] **Option 3 — accept, explicitly.** Only if no patched `SSH.NET` exists yet. Then: record it
      in `STATE.md` `## Known drift` with a named owner and a review date, and make
      `ci.ps1` fail on any vulnerable package **except** this one specific advisory id, so the
      gate goes green for the right reason and a *new* advisory still turns it red. A blanket
      severity threshold or a disabled gate is not acceptable — that trades one silent failure
      for a worse one.
- [ ] Whichever option lands, `./backend/scripts/ci.ps1` reaches the vulnerable-dependency gate
      green. Paste the output.
- [ ] `backend/docs/ASSUMPTIONS.md` §3.8 updated to record what was actually done and why.

## Out of scope

- Removing `Testcontainers.PostgreSql`. It is currently unexercised — Docker is absent locally
  and CI uses a Postgres service container — so removal is tempting. Do not. The "install Docker
  and the tests just run" path is a deliberate developer-experience property of the harness, and
  deleting it to dodge an advisory in an unused code path is the wrong trade. If you think it
  should go, raise it; do not decide it inside this card.
- Any of the other outdated packages `dotnet list package --outdated` reports. A general
  dependency sweep is its own card with its own justification (§8).
- Any change to `backend/src/**`. This is a test-dependency card.
