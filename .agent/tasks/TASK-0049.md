# TASK-0049 — Audit log read surface and CSV export

Owner: backend-dev
Depends on: **TASK-0048** — the `audit_event` table. Do not start until it is closed.
Contract impact: **additive** — two new read endpoints, one new DTO, one new page type.
Status: done

## Goal

An `audit.view` holder can answer spec 6.1.12's motivating question in one screen: "a parent comes
to the office in March insisting their child scored 62 in Mathematics and the sheet says 26." That
means filtering the log by date range, actor, action, entity type and outcome, newest first. An
`audit.export` holder can take the same filtered set as CSV, **and that export is itself an audit
event.**

## Contract delta — additive

| Endpoint | Privilege | Notes |
|---|---|---|
| `GET /api/v1/audit-events` | `audit.view` | Cursor-paged. Five filters, all optional and combinable. Sorted **newest first by default**. |
| `GET /api/v1/audit-events/export` | `audit.export` | `text/csv`. Same five filters. **Writes an `audit_event` with action `audit.export` before returning.** |

Filters, per 6.1.12: `fromUtc` / `toUtc` (date range), `actorAdminId`, `action`, `entityType`,
`outcome`. Follow `ListAdminAccounts.cs` and `ListRoles.cs` for the existing query/filter/cursor
shape — do not invent a second paging convention. `CursorPageOfAuditEventDto` will render from the
existing `CursorPage<T>`.

**No mutating endpoint exists, and that is deliberate.** Spec 6.1.12: "Entries cannot be edited or
deleted through any interface, and no endpoint exists that would allow it." Do not add one, and do
not add a soft-delete flag.

## Acceptance criteria

- [x] `GET /audit-events` gated by `audit.view` declaratively (`.RequirePrivilege(...)`) — the
      privilege is not data-dependent, so it belongs on the route, not resolved in the handler.
- [x] All five filters work individually **and in combination**; at least one test combines three
      of them and asserts the intersection, not just that each filter runs.
- [x] Default sort is `occurred_at` **descending**, and a test asserts the default with no sort
      parameter supplied. `id` is monotonic (TASK-0048), so use it to break ties deterministically
      — two events in the same millisecond must come back in a stable order or the cursor will skip
      or repeat rows.
- [x] Cursor paging proven across a page boundary: seed more rows than one page, walk every page,
      assert the union is exactly the seeded set with no duplicate and no gap.
- [x] `GET /audit-events/export` gated by `audit.export`, returns `text/csv`, honours the same five
      filters, and **writes its own `audit_event` row with action `audit.export`** — asserted by
      reading the log back after an export. An export that does not log itself fails this card.
- [x] The export's own audit row records the filters used (in `after_json` or metadata), so "who
      exported what" is answerable. Exporting the whole log and exporting one pupil's rows must be
      distinguishable after the fact.
- [x] **PII (§8):** the CSV carries `actor_label` (a name and email, which 6.1.12 requires) but must
      never widen beyond the columns 6.1.12 defines, and `source_ip` stays truncated as stored.
      Do not add a "helpful" full-IP or resolved-name column.
- [x] An account holding `audit.view` but NOT `audit.export` gets 403 on the export route and 200
      on the list route. Both asserted — this pair is the whole reason 6.1.12 names two privileges.
- [x] `openapi.json` regenerated via `scripts/generate-openapi.ps1 -Promote`; `CONTRACT.lock`
      updated; the diff is additive only (no existing path or schema changes shape).
- [x] All ten §9 gates green, `SUMMARY` pasted — **run by the ORCHESTRATOR, not by you.** See

## Notes for the implementing agent

Read spec `03-module-admin-roles-audit.md` §6.1.12 — the last two paragraphs are the ones that
matter here (reading requires `audit.view`, filterable by those five dimensions, newest first,
export requires `audit.export` and is itself an event).

Read `Auth/AdminAccounts/ListAdminAccounts.cs` + `ListAdminAccountsHandler.cs` **first**. They are
the closest existing precedent for a filtered, cursor-paged, privilege-gated list, and TASK-0027
already solved the cursor-stability problem you are about to meet. Do not write a second paging
convention.

**The tie-break is not a detail.** `occurred_at` is not unique — 6.1.12 chose a BIGSERIAL `id`
precisely so that ordering is unambiguous inside one millisecond. A cursor keyed on `occurred_at`
alone will silently skip or duplicate rows under load, and a test that seeds rows at distinct
timestamps will never catch it. Seed at least two rows with an identical `occurred_at` and assert
stable ordering.

For the CSV: stream it rather than buffering the whole filtered set in memory. The log is the
largest table in the product by design (seven-year retention, every score edit) and an unbounded
export is a memory profile, not a feature.

Size: if you pass roughly 900 lines of production code, stop and report.

  cheapest place to fix a contract hole is the card that owns the endpoint.
