## Goal

The head teacher approves an arm's submitted result set, or sends it back to the class teacher with a reason. The class teacher
sees that reason on every sheet of the arm, corrects, recomputes and resubmits; TASK-0088's submit already clears the reason.
A set can be returned any number of times, from Awaiting Approval or from Approved.

## Contract delta (approved)

1. `POST /api/v1/result-sets/{resultSetId}/approve`, operation `ApproveResultSet`, needs `result.approve`, scoped `ResultSet` exactly like
   `SubmitResultSet` (a school-wide grant satisfies it). No body. CSRF required, and `Idempotency-Key` accepted but not required, as on submit.
   `200 ApproveResultSetResponse {resultSet: ResultSetSummaryDto, approvedAt}`. `409 result_set.not_awaiting_approval` from any other
   state. `409 result_set.needs_recompute` when the flag is set (§6.2.9), with §6.7.12's message: "Marks have changed since the last
   computation. Run computation again before approving." Unknown id: 403 (TASK-0071 ruling), and there is no 404.
2. `POST /api/v1/result-sets/{resultSetId}/return`, operation `ReturnResultSet`, needs `result.return`, with the same scoping and headers.
   Body `ReturnResultSetCommand {reason}`: trimmed, 10–500 characters, else `422` (the spec's own bounds, §6.7.8 and §6.7.3). Allowed from
   Awaiting Approval and from Approved, else `409 result_set.not_returnable`. `200 ReturnResultSetResponse {resultSet: ResultSetSummaryDto}`.
3. `ResultSetSummaryDto` gains **`returnReason: string|null`** (response-required, nullable). This is additive on a response, as
   `SectionDto.ratesTraits` was (TASK-0083). It is populated at all 7 `new ResultSetSummaryDto(` sites; grep them. Without it the
   reason §6.7.8 says the class teacher sees at the top of their sheet reaches no endpoint.

Error codes use the `result_set.*` form, as `SubmitResultSetHandler.cs` does. Copy its constants' style.
