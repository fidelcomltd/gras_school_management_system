## Why it is blocked, not merely queued

Spec 6.3.7's promotion proposal reads, for every pupil, an `annual_result` row and applies
`promotion_threshold`, `pass_mark` and `require_core_pass` from settings. It then writes a
`promotion_batch`, one `promotion_decision` per pupil, closes each pupil's enrolment and opens a
new one in a target arm of the next level.

Not one of `arm`, `pupil`, `enrolment`, `annual_result` or the class-level progression chain
exists. Every rule in 6.3.7 is a rule *about* those entities, so the module cannot be written now,
only faked — and a promotion that proposes outcomes from absent results is worse than no
promotion. Split out of spec 6.3 by TASK-0035 on the same reasoning that split TASK-0030 out of
TASK-0028.

## Scope sketch (expand before dispatch)

- `GET /sessions/{id}/promotion/preview` · `POST /sessions/{id}/promotion` ·
  `POST /promotion-batches/{id}/reverse`. Privileges `promotion.run`, `promotion.reverse`,
  `promotion.decide` — **all three constants already exist** in `Domain/Security/Privileges.cs`.
- Preconditions: Third Term closed; the new session exists with an arm for every receiving level
  (6.3.7's message names the level with no arm); annual results computed for every arm promoted
  from.
- Three outcomes: Promoted (→ Graduated at the terminal level, status change, **no** new
  enrolment), Repeat, and **Promoted on trial — never system-proposed**, only chosen by a holder
  of `promotion.decide`, with a mandatory reason.
- Balanced round-robin target-arm distribution by descending annual average; editable per row;
  over-capacity **warns, never blocks** (6.4.9).
- Commit is ONE transaction — "a failure on pupil forty of two hundred leaves nothing applied."
- Reversal: `promotion.reverse` + Super Admin + reason; allowed only while no mark has been
  entered and no pin used in the new session; refused with 6.3.7's exact message otherwise. The
  batch row is KEPT and marked reversed, never deleted.
- Edge cases from 6.3.9 that belong here: promotion run twice (at most one non-reversed batch per
  session); pupil withdrawn between publication and promotion (excluded, shown in a separate
  collapsed list); pupil with no annual result (included, outcome blank, warning, administrator
  must choose); terminal-level pupil with a failing average (proposed Graduated regardless,
  overridable to Repeat).
