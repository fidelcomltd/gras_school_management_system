> **Naming trap, read this first.** "Session" in this card means an ACADEMIC session (spec 05
> §6.3) — a school year, `2026/2027`. It has nothing to do with the auth/login session of
> CLAUDE.md §5, and this card is **not** a §5 change and needs no §5 sign-off. The codebase
> already uses both senses: `Privileges.Admin.SessionRevoke` (`admin.session.revoke`) is the auth
> one; `Privileges.Session.*` is this one. Do not unify them.

## Goal

A school year and its three terms can be created, edited and moved through their lifecycle, with
the database — not the application — guaranteeing that only one term is ever active. This is the
entity every later module hangs off: an arm belongs to a session, a mark belongs to a term, a
result set belongs to an arm and a term.

## Contract delta

All additive. Privileges per spec 6.3.2, and **every constant already exists** in
`Domain/Security/Privileges.cs` (`Session.View/Create/Update`, `Term.Open/Close`) — do not invent
new codes or touch the register.

| Endpoint | Privilege | Notes |
|---|---|---|
| `GET /api/v1/sessions` | `session.view` | List. Cursor-paginated per spec 9.5 even though 6.3.8 says the list is short — one pagination shape for the whole API (§8). |
| `POST /api/v1/sessions` | `session.create` | Creates the session **and all three terms in one transaction**. `Idempotency-Key` REQUIRED. |
| `GET /api/v1/sessions/{id}` | `session.view` | Detail with its three terms. |
| `PATCH /api/v1/sessions/{id}` | `session.update` | Name and dates, while `upcoming` or `active`. |
| `PATCH /api/v1/terms/{id}` | `session.update` | Dates, label, `timesSchoolOpened`, `nextResumptionDate`. |
| `POST /api/v1/terms/{id}/open` | `term.open` | Precondition failures return the naming message, not a bare 409. |
| `POST /api/v1/terms/{id}/close` | `term.close` | Same. |
| `POST /api/v1/terms/{id}/reopen` | `term.close` **plus** `isSuperAdmin` | Reason ≥ 10 chars. |

Enums (`upcoming`/`active`/`closed`) cross as strings; the client must tolerate an unknown member
(§8). Dates are dates, not timestamps — but anything with a time component stays
`DateTimeOffset` UTC per §8.

## Acceptance criteria

- [x] `academic_session` per 6.3.3: name `YYYY/YYYY` where the second year is **exactly** the
      first plus one (reject `2026/2028` with 6.3.3's message), unique; `start_date` inside the
      first named year, `end_date` inside the second, start before end.
- [x] Sessions cannot overlap (6.3.9), rejected with the real dates in `detail`.
- [x] `POST /sessions` creates exactly three terms with ordinals 1, 2, 3 in ONE transaction, all
      `upcoming`, session `upcoming`. **No route exists that creates a session without terms** —
      a test asserts there is no such path, because 6.3.5 makes that a state the school must
      never reach.
- [x] `ordinal` is immutable; `name` is an editable label; all logic keys off `ordinal`.
- [x] Term dates: inside the session range, each term later than the previous term's end, no
      overlap — rejected with 6.3.4's message naming both terms and both dates.
- [x] `times_school_opened` 1..200, nullable while `upcoming`/`active`, **required to close**
      (6.3.9's message), and **immutable once closed** (6.3.6).
- [x] **A partial unique index enforces one active term across the whole system, and one active
      session** (6.3.9 is explicit that the database does this, not the application). A test
      proves it by attempting the second activation directly against the database, bypassing the
      application layer entirely — an application-level check alone does not satisfy this.
- [x] `open` preconditions that need no other module: previous term in the session is `closed`,
      or this is ordinal 1 and the previous session is `closed`/has no active term; session has
      both dates. Blocking response **names the reason** in 6.3.6's wording.
- [x] `close` sets `closed_at`/`closed_by`; a closed term returns **409** from score-entry-shaped
      writes. No score endpoints exist yet, so assert this at the domain guard, not by inventing
      an endpoint to reject.
- [x] `reopen`: `term.close` + `isSuperAdmin` + reason ≥ 10 chars, and **refused outright if the
      following term has already been opened** (6.3.6).
- [x] Audit events per §6 wherever the module writes; no PII in logs (§8).
