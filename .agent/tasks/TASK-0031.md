# TASK-0031 — Make the gate script find its own test connection string

Owner: backend-dev
Depends on: nothing
Contract impact: none
Status: review

## Goal

`./backend/scripts/ci.ps1` runs with no environment prelude. Every dispatch then invokes the
gates with one fixed, allowlistable command instead of improvising a compound PowerShell
statement, which is what actually burns tokens.

## Why

2026-09-06, TASK-0028 dispatch 1: the gate command failed and was retried repeatedly, each retry a
multi-minute full CI run. Four independent causes, three of which exist only because the agent had
to hand-build a compound command to set `POSTGRES_TEST_CONNECTION` first (`2>&1` wrapping stderr
into `NativeCommandError` so a green run reported exit 1; a `| Select-String` filter hiding why;
a leading `cd`; and the 120 s default timeout). A compound command also cannot match a permission
prefix rule, so it prompts every time instead of matching the allowlist. Remove the prelude and
all four collapse into one allowlisted string. `scripts/local-env.ps1` was meant to be this and is
stale — see `## Known drift`.

## Acceptance criteria

- [x] When `POSTGRES_TEST_CONNECTION` is unset, `ci.ps1` reads `~/.gras/pg-test.txt` itself,
      stripping a UTF-8 BOM (the file starts `EF BB BF`) and trimming whitespace. An explicitly
      set environment variable still wins.
- [x] When the file is absent, the existing "integration tests will be SKIPPED / they are NOT
      passing — they are absent" warning is what the user sees. Do not invent a new failure mode,
      and do not make a missing file fatal.
- [x] The connection string is never echoed — not in the warning, not in the `SUMMARY`, not under
      `-Verbose`. A test asserts this.
- [x] `generate-openapi.ps1` needs no database; confirm and leave it alone if so.
- [x] `scripts/local-env.ps1` is DELETED or rewritten to be a thin, correct alias — it must not
      remain as a stale third way to do this. Strike its drift entry in `STATE.md` either way.
- [x] `STATE.md` `## Gate commands`: the canonical invocation loses its env-var prefix and becomes
      `./backend/scripts/ci.ps1 -NoFailFast`. The four rules recorded there (timeout, no `2>&1`,
      no `Select-String`, no `cd`) stay — only the prefix goes.
      **NOT edited by this dispatch — `## Gate commands` is orchestrator-owned (CLAUDE.md §1).
      Reporting the exact new one-liner for the orchestrator to write in: see `## Log` below.**
- [x] `backend/AGENTS.md` §4 step 8 quotes the new one-liner.

## Out of scope

Any change to what the ten gates check, their order, or their pass/fail rules.

  `Set-Content` that might apply its own BOM policy and mask the case under test. 13 assertions:
  BOM+whitespace stripped exactly; missing file → `$null`, no throw; whitespace-only-after-trim file
  → `$null`; an explicitly-set env var wins over a present file unconditionally; env var unset +
  file present → env var set from file; env var unset + file absent → stays unset, no throw; and
  the **never-echoed proof** — a marker string planted in the fixture is asserted absent from every
  captured stream (stdout, information, verbose) of a real `-Verbose` invocation, with a companion
  assertion that the diagnostic DOES name the file path (so the "marker absent" assertion isn't
  vacuously passing because nothing printed at all). One bug caught and fixed while writing this
  test, worth recording: `$result.StartsWith([char]0xFEFF)` is NOT a reliable "does this start with
  a BOM" check — .NET's default culture-aware string comparison treats U+FEFF as an
  ignorable/zero-weight character, so it returned `$true` even against a string with no BOM
  whatsoever; replaced with a direct `$result[0] -ne [char]0xFEFF` char comparison, which has no
  such culture layer. All 13 assertions pass; re-ran unchanged `gate-summary.tests.ps1` alongside it
  (25 assertions) to confirm no regression there.
