# TASK-0011 — Make the secret-scan gate pass for the right reason

Owner: backend-dev
Depends on: TASK-0008 (which installed gitleaks and thereby surfaced this)
Contract impact: none
Status: done

## Goal

`ci.ps1`'s Secret scan gate is red. It is red because TASK-0008 installed `gitleaks`, so the gate
executed for the first time in this repo's life — before that it printed `PASS: Secret scan` while
scanning nothing. Nine findings surfaced. **All nine were inspected by the orchestrator on
2026-08-27 and none is a real credential.** The gate must go green by fixing what is actually
wrong — an over-broad rule and an integrity hash mistaken for a key — not by disabling scanning.

## The finding

Gate invocation (`ci.ps1` line 251, run from `backend/`):
`gitleaks detect --source . --config .gitleaks.toml --redact --no-banner` → `leaks found: 9`.

Two families:

**A. `postgres-connection-string-with-password` — 5 hits, every one a documented placeholder.**
```
backend/README.md:51                                          Username=YOUR_USER;Password=YOUR_PASSWORD
backend/README.md:145                                         Username=...;Password=...
backend/src/SchoolManagement.Api/appsettings.Development.template.json:39   Username=<user>;Password=<pw>
backend/src/SchoolManagement.Infrastructure/Persistence/DesignTimeDbContextFactory.cs:24   (doc comment) Password=...
backend/ci/github-actions-backend.yml:111                     HISTORY ONLY — that path no longer exists
```
Root cause: the rule's regex (`backend/.gitleaks.toml:25`) is
`(?i)(host|server)\s*=\s*[^;"'\s]+;[^"']*password\s*=\s*[^;"'\s]{1,}` — it has **no `stopwords`
and no `allowlist`**, so `Password=...` and `Password=YOUR_PASSWORD` match as readily as a real
one. The rule was written 2026-08-03 and, because gitleaks was never installed, **has never run
until now**. It is untested, not wrong in intent.

**B. `generic-api-key` — 4 hits, all the SHA-256 contract hash.**
```
.agent/STATE.md:40, :58        openapi.json sha256: 228ae57f...
contracts/CONTRACT.lock:3      (x2 — current and an earlier commit)
```
A 64-hex integrity digest published on purpose. Not a credential in any sense.

**Note on history:** the gate scans git history by default, so 4 of the 9 (the moved workflow file,
the older `STATE.md` line, the earlier `CONTRACT.lock` commit) **cannot be cleared by editing
current files.** Any solution that only edits working-tree content will not turn this gate green.

TASK-0008's own guidance — "make the example obviously fake rather than adding an allowlist entry"
— was the right default but does not apply here: these examples are *already* obviously fake
(`YOUR_PASSWORD`, `...`, `<pw>`) and trip the rule regardless, and history is immutable.

## Contract delta

## Acceptance criteria

- [x] Family A fixed by **narrowing the rule, not excusing the files**: add `stopwords` (or a
      tight `allowlist.regexes`) to `postgres-connection-string-with-password` covering literal
      placeholder text — at minimum `YOUR_PASSWORD`, `YOUR_USER`, `<pw>`, `<user>`, a bare `...`,
      `***`. Scope it to the rule, not to a path.
- [x] Family B fixed by teaching `generic-api-key` that a 64-character hex digest is not a key, or
      by a path-scoped allowlist for `contracts/CONTRACT.lock` and `.agent/STATE.md`. State which
      you chose and why in the config as a comment.
- [x] **Proof the gate still catches a real leak.** After the change, write a realistic
      credential-shaped connection string (fake host, fake but non-placeholder-looking password) to
      a scratch file, show gitleaks flagging it, then delete the scratch file. A gate that passes
      because it stopped looking is a worse outcome than the red gate it replaced. Paste both runs.
- [x] `./backend/scripts/ci.ps1` reaches `PASS: Secret scan` with the scan actually executing.
      Paste the output including the `commits scanned` line.
- [x] `backend/docs/ASSUMPTIONS.md` §3.9 (written by TASK-0008) updated to record the resolution.
- [x] No `.gitleaks.toml` change that disables a rule outright, drops history scanning
      (`--no-git`), or lowers the gate to a severity threshold.

## Out of scope

- **A `--baseline-path` baseline file.** Considered and rejected by the orchestrator: it is
  gitleaks' idiomatic answer for pre-existing findings, but it freezes all nine as accepted and a
  careless regeneration later silently swallows a real leak. Fixing the over-broad rule addresses
  the cause instead. Raise it if you disagree; do not decide it inside this card.
- Editing `backend/README.md`, the appsettings template, or `DesignTimeDbContextFactory.cs` to
  reword their examples. Four findings live in git history and would survive it, so this cannot
  work — and those examples are good documentation.
- Rewriting git history. Not for nine non-secrets.
- Anything about `POSTGRES_TEST_CONNECTION`'s privileges — that is `STATE.md` Open question 10.
