# TASK-0075 — Gate the ledger's contract block against the lock, so it stops going stale

Owner: backend-dev
Depends on: nothing.
Contract impact: **none** — a new gate in `ci.ps1`. No `src/**` change, no endpoint change, no
regeneration, and the contract document itself is not touched.
Status: done — closed 2026-09-16
Reads: `backend/scripts/ci.ps1` — the `OpenAPI contract drift` gate at ~lines 534-567 is the model

## Goal

`.agent/STATE.md`'s `## Contract` block names the current contract hash, path count and schema
count in prose. **It has gone stale three separate times in the same way** — TASK-0055 → 0062,
then 0062 → 0063, then 0063 → 0069 — each time because a closing card updated the archive and not
the block. It was caught the third time only because the orchestrator happened to verify the hash
with `sha256sum` before writing a card that depended on it; had it not, a `frontend-dev` dispatch
would have gone out naming a contract hash that no longer existed.

`contracts/CONTRACT.lock` has been correct every single time. **The prose is the thing that drifts,
and it drifts silently.** This card makes it impossible to drift silently.

## Contract delta

None.

## What to check — three assertions, not one

The orchestrator described this to the human as "a one-line check". Reviewing `ci.ps1` to write the
card found a third gap that makes it worth slightly more than that:

1. **`CONTRACT.lock`'s recorded `openapi.json.sha256` equals the actual SHA-256 of
   `contracts/openapi.json`.** **Nothing checks this today.** The existing `OpenAPI contract drift`
   gate compares the GENERATED document against the COMMITTED one and never reads the lock at all,
   so the lock is trusted by every agent and verified by nothing. It happens to be correct; that is
   luck, not a guarantee.
2. **`STATE.md`'s `## Contract` "Current:" hash equals that same hash.** This is the drift that has
   actually bitten, three times.
3. **`STATE.md`'s stated path and schema counts equal the live document's.** These drifted alongside
   the hash each time (the block read 51 paths / 93 schemas while the document held 54 / 102).

## Acceptance criteria

- [x] A gate in `ci.ps1` asserting all three. Put it beside the existing `OpenAPI contract drift`
      gate and follow its shape — a clear red explanation naming the fix, then `throw`.
- [x] **It FAILS the gate, it does not warn.** A warning is functionally what exists now: three
      silent misses. Rationale recorded so it is not softened later without a decision.
- [x] **The failure message names `.agent/STATE.md` `## Contract` as the thing to fix, and says the
      ORCHESTRATOR owns it.** This matters: a dev agent cannot write `.agent/**`, so for them this
      gate is a STOP-and-bounce signal, not a task. Say so in the message itself — a dev agent that
      reads "fix STATE.md" and cannot will either guess or stall.
- [x] Assertion 1 fails independently of 2 and 3, and the message distinguishes them. "The lock is
      wrong" and "the ledger is wrong" are different problems with different owners.
- [x] **Proven able to fail — all three, separately** (`STATE.md` 2026-09-05 standing lesson: *a
      check that cannot be shown to fail is not a check*). Corrupt the lock hash, watch it go red,
      revert. Change the STATE.md hash by one character, watch it go red, revert. Change a count,
      watch it go red, revert. **Report all three red runs plus the green one.** A gate accepted on
      a green run alone is exactly what this project has been burned by.
- [x] Runs in the cheap tier: file reads only, no database, no build output needed. It must surface
      in seconds (`CLAUDE.md` §3, cheapest gate first).
- [x] **No new tool dependency.** Use PowerShell's own JSON handling — do NOT shell out to `jq`.
      `jq` appears in `STATE.md`'s guidance for agents but is NOT in its toolchain list, so it
      cannot be assumed present on a developer machine or on the runner.
- [x] A self-test under `backend/scripts/tests/` in the style of the existing ones, against fixtures.
      **Note the 2026-09-05 drift entry on `gate-summary.tests.ps1:101,:108` before writing
      assertions: `-match` substring checks there are near-unfalsifiable. Do not reproduce that.**

## Notes for the implementing agent

The block's current shape, which your parser must handle — note the backticks and the `·`
separators, and that the counts are bolded:

```
**Current: `152dc1c27db77bfc6c2697580d8b3f86ebe16af42a828360ce235a6c6f215d0f`** · **54 paths** ·
**102 schemas** · api version `v1` · moved 2026-09-16 by TASK-0069 ...
```

It wraps across lines and the prose after it changes every time. **Anchor on `Current:` and the
backticked hash, and on the `N paths` / `N schemas` tokens — do not assume a fixed line count, a
fixed position, or that the trailing prose has any particular shape.** A brittle parser here would
itself become a source of false reds, which is worse than the drift it replaces.

`CONTRACT.lock` starts with a UTF-8 BOM (`postgres-test-connection.ps1` documents the same hazard
for a different file, with the `TrimStart([char]0xFEFF)` fix). Strip it rather than discovering it.
