- **Both operations are `get` only.** There is deliberately no mutating audit endpoint (spec
  6.1.12: entries "cannot be edited or deleted through any interface"). Do not add a wrapper for
  one, and do not treat its absence as an oversight.
- **`ListAuditEvents` query parameters — all NINE OPTIONAL, none required:** `cursor`, `pageSize`,
  `fromUtc`, `toUtc`, `actorAdminId`, `action`, `entityType`, **`entityId`**, `outcome`. Verified:
  `jq '.paths["/api/v1/audit-events"].get.parameters[] | "\(.name) required=\(.required)"'` returns
  `required=null` for all nine. (`entityId` was added by TASK-0055 after this card was first
  written — it is the filter that makes spec 6.1.12's one-child scenario expressible.)

- **`ExportAuditEvents` takes only SEVEN of those nine — it has NO `cursor` and NO `pageSize`,**
  because it streams the entire filtered set rather than paging. Its parameters are `fromUtc`,
  `toUtc`, `actorAdminId`, `action`, `entityType`, `entityId`, `outcome`, all optional. Verified
  with the same `jq` against `.paths["/api/v1/audit-events/export"]`.
  **This asymmetry is a genuine negative-typing proof and you should use it:** passing `cursor` or
  `pageSize` to `ExportAuditEvents` must fail typecheck, while passing either to `ListAuditEvents`
  must succeed. Two operations on the same resource with deliberately different parameter sets is
  the most interesting typing shape in this move after `text/csv`.
- **Neither operation takes `X-CSRF-Token` or `Idempotency-Key`.** Both are reads. So **this move
  supplies NO new instance of either the omitted-required-header or the rejected-header
  direction** — if you want those proofs, reuse an existing operation, or state plainly that this
  move offers none. **Do not fabricate one.** (That instruction is what made TASK-0052 go right.)
- **Neither operation has a path parameter**, so there is no `{id}` → `:id` MSW conversion to
  exercise and no omitted-required-path-parameter proof available here. Note it in the test comment
  for the next copier, as TASK-0052 did.
- New schemas: `AuditEventDto`, `CursorPageOfAuditEventDto`, `AuditOutcome`.
- **`AuditOutcome` has exactly two members, `Success` and `Rejected`** — PascalCase, like every
  other enum in this contract. Prove §8 unknown-member tolerance via a `server.use(...)` override
