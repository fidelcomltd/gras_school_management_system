## Goal

An administrator can read and change the result rules the computation engine obeys: tie-break,
position scope, level position, pass mark and minimum subjects for position. The annual and
promotion fields are stored too, so the annual and promotion cards find them. A fresh database has
§6.2.8's defaults.

## Contract delta (approved)

| Op | Path | Privilege | Success | Errors |
|---|---|---|---|---|
| GetResultRules | `GET /api/v1/settings/result-rules` | `settings.view` | 200 `ResultRulesDto` | — |
| UpdateResultRules | `PUT /api/v1/settings/result-rules` | `settings.resultrules.update` | 200 `ResultRulesDto` | 422 validation; 409 `result_rules_locked` naming the locked field |

`ResultRulesDto` = request body: `annualMethod` (`simple_average`/`weighted`), `weightFirst`,
`weightSecond`, `weightThird` (int|null), `primaryPositionScope` (`arm`/`level`),
`showLevelPosition`, `tieBreakRule` (`shared_position`/`exam_then_ca`/`exam_then_alphabetical`),
`passMark`, `promotionThreshold`, `requireCorePass`, `coreSubjectIds` (uuid[]),
`minSubjectsForPosition`. The PUT carries the reason field exactly as `PUT /settings/assessment` does
under §6.2.9, if that handler requires one. Match it, don't invent.
