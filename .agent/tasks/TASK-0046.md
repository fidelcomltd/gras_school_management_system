## Goal

Split from TASK-0030 on 2026-09-08 and never carded until now. What an administrator needs around assignments once a
school uses them in earnest: to see who holds what by name, to carry a year's allocation into the next session without
re-entering it, and for assignments to stay honest when roles, arms and sessions change underneath them.

## A — read surface (`feat/assignments-read-surface`)

- `RoleAssignmentDto` gains response-required `roleName`, nullable `sessionName` (null only for the sessionless Super

- `AdminAccountSummaryDto` (`GET /admins`) gains `rolesHeld` (distinct active role names, sorted; `["Super Admin"]` for
  a super admin, as `/auth/me`'s `roleNames`) and `scopeSummary` (spec 6.1.8: `School-wide`, or the class count and the
  first two class names, e.g. `3 classes: Primary 2A, Primary 5B, …`; empty when nothing is held).
- Fix the recorded drift: `CreateRoleAssignmentHandler` may return a default `createdAtUtc` (stamped at SaveChanges).
- Frontend: the Roles section reads names from the DTO (no more resolving from three lists, and no "name needs
  role.view" gap); the admin list shows Roles held and Scope columns.
- Tests: names on list and create; `rolesHeld`/`scopeSummary` for school-wide, arm-list and no-role accounts.

## B — copy to session (`feat/assignments-copy-to-session`)

`POST /assignments/copy-to-session` (6.1.14, 4.2.2), body `{ fromSessionId, toSessionId, dryRun }`, privilege
`role.assign`. For every ACTIVE assignment in the source session: a school-wide one copies as is; an arm-list one maps
each arm to the target session's arm with the same level and label, and is **skipped with a reason** when any arm has no
match (never silently narrowed). Skipped too: already present in the target (same account, role, scope and arms), an
archived role, a deactivated account, the sessionless Super Admin assignment. Rule 3 applies per copied assignment (a
caller never copies wider than their own scope); rule 1 means the caller's own assignments are skipped. Target must not
be Closed. The dry run returns the same `{ created[], skipped[{…, reason}] }` and writes nothing; the real run writes
them in one transaction with one audit event per created assignment. UI: a "Copy assignments from…" action on the admin
list, dry run shown for review before the write (4.2.2: "presents the list for review before writing").

**Open question for the lead, blocking the second half of B only:** TASK-0060 left non-scopable operations (settings,
accounts, roles, rule 3, form-teacher and subject checks) accepting a school-wide grant from ANY session. Spec 4.2.2
("last session's assignments do not carry over") implies they should follow the active session. Enforcing it strands
every non-Super-Admin who was not copied at the first term opening, which is why it waits for copy-to-session.
Options: (a) enforce with B, since copy-to-session is the remedy; (b) leave any-session for non-scopable operations.
**RULED (a) by the lead, 2026-09-28.**

## C — lifecycle (`feat/assignments-lifecycle`) — spec 6.1.13

- Assigning an **archived** role: 409 `role_assignment.role_archived` ("This role is archived and cannot be newly
  assigned."). Existing assignments of an archived role keep working (6.1.4), as today.
- Assigning in a **Closed** session: 409 `role_assignment.session_closed` ("The session 2025/2026 is closed. Assignments
  can only be made in an open session."). Today neither is checked.
- **Arm deleted under an assignment:** the arm is removed from every assignment's arm list; an emptied assignment is
  revoked with an audit event. Same transaction as the delete.
- **Form teacher reassigned mid-term:** the spec's behaviour is revoke-then-create, which the existing endpoints and UI
  already do; no automatic link between `Arm.FormTeacher` and a Class Teacher assignment exists or is added. Record it.

## Decided

- **`/auth/me` additions stay out.** `/auth/me` already returns the effective privilege set with scopes and
  `roleNames`; the admin detail now carries the assignments with names. Nothing on the frontend needs more.
- **6.1.8 list filters** (role, scope arm, session) are not built here; recorded for the admin-list polish.
