## Goal

The orchestrator can run every cheap gate in full plus a named slice of the integration suite, in
minutes instead of ~1 hour, without hand-assembling `dotnet` commands and without the silent-skip
trap that hand-assembly walked into on TASK-0063. CI keeps running the whole thing, unchanged.

## Contract delta

None.

## Acceptance criteria

- [x] `-SkipIntegration` runs gates 1-5 and 8-10 and skips the integration stage. The SUMMARY says
      plainly that integration was SKIPPED BY REQUEST — it must never read like a pass.
- [x] `-IntegrationFilter <expr>` passes the expression to `dotnet test --filter` for the
      integration stage only, leaving every other gate untouched and full.
- [x] **The coverage gate does not fail merely because integration was scoped or skipped.** Today it
      fails on any unclean run; under `-SkipIntegration` or `-IntegrationFilter` it must be reported
      as NOT APPLICABLE rather than FAIL, because a partial run's coverage number is meaningless.
      Getting this wrong makes the whole flag useless — the run still exits non-zero.
- [x] **`Skipped > 0` still fails the run, in every mode.** The `-AllowSkipped` escape stays exactly
      as it is. A test skipped because it could not reach Postgres must still be a failure, never
      conflated with a stage skipped by request. This is the distinction the card exists to make
      safe — see the closing note on TASK-0063.
- [x] A filtered run that matches ZERO tests is a FAILURE, not a pass. A typo'd filter must not
      report green — this is the same false-green class as the silent skip.
- [x] Default behaviour with no new flags is byte-identical to today's, proven by a run.
- [x] `.github/workflows/backend-ci.yml` passes neither new flag and its behaviour is unchanged.

## Notes for the implementing agent

`ci.ps1` already has `-NoFailFast`, `-AllowSkipped` and `-SkipContractDrift`, so the parameter and
gate-reporting conventions you need are in the file — follow `-SkipContractDrift`'s handling
(`ci.ps1:381`) rather than inventing a new shape.

**The trap this card exists to remove.** On TASK-0063 the orchestrator hand-ran
`dotnet test --filter` to re-try one dropped test. It reported `Failed: 0, Passed: 0, Skipped: 1`
and **exited 0**, because a raw `dotnet test` does not resolve `POSTGRES_TEST_CONNECTION` — only
`ci.ps1` does, from `~/.gras/pg-test.txt`. Reading the exit code would have closed the card on a
test that never ran. Your `-IntegrationFilter` path must go through the script's existing connection
resolution, so a scoped run cannot fail that way.

**Gates.** `.agent/rules/gates.md` section 1: report counts, stop. You are modifying the gate script
itself, so prove it by running it: default mode, `-SkipIntegration`, a matching `-IntegrationFilter`,
and a deliberately non-matching one. Paste the SUMMARY block from each.
