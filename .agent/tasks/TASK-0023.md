# TASK-0023 — Make the frontend unit tests hermetic in their environment

Owner: frontend-dev
Depends on: none (blocks PR #9 — frontend-ci is red)
Contract impact: none
Status: done

## Goal

`npm run test` passes on a machine with **no `frontend/.env` at all**, which is what every CI
runner is. Unit tests stop depending on an untracked developer-machine file.

## The failure

`frontend-ci`, job `quality-gates`, step `Test`: **all 15 test files fail with `0 test`** — they
die during collection, before a single case runs.

    Error: Invalid environment configuration.
      - VITE_APP_NAME: Invalid input: expected string, received undefined
      - VITE_APP_ENV: Invalid option: expected one of "development"|"staging"|"production"
      ... (all six variables)
     ❯ readEnv src/config/env-values.ts:42:11
     ❯ src/config/env-values.ts:51:13
     ❯ src/lib/auth/auth-session.ts:1:1

Chain: `frontend/.env` is gitignored (`.gitignore:23`); only `.env.example` is committed.
`vite.config.ts`'s `test` block sets no `env`, so vitest falls back to Vite's ordinary `.env`
loading, which finds a developer's local file and nothing on a runner. `env-values.ts:51` runs
`readEnv(import.meta.env)` at MODULE SCOPE, so the throw happens at import time — and
`src/test/setup.ts` imports `auth-session`, which imports `env-values`, so it reaches every file.

**Same family as TASK-0022**: a gate that passes locally only because of an input that exists
solely on the developer's machine. It has never passed in CI.

## Acceptance criteria

- [ ] `vite.config.ts`'s `test` block declares an explicit `env` with all six `VITE_*` variables,
      so the suite is hermetic and cannot be affected by the presence, absence or contents of any
      `.env`. Use obvious test values, not production-looking ones.
- [ ] **Prove it the only way that counts: temporarily move `frontend/.env` aside, run
      `npm run test`, and show it green.** That is the CI condition reproduced locally. Restore
      the file afterwards. A run with `.env` present proves nothing about the bug.
- [ ] `src/config/env-values.test.ts`'s case `loads the real .env without throwing` asserts that a
      developer-machine file exists — it is the defect stated as a test. Reframe it to assert the
      module loads and exports sane constants under the CONFIGURED test env. Keep the real
      assertions (`API_BASE_URL` matches `^https?://`, no trailing slash, leeway divisible by
      1000). **Do not delete the case to make the suite green.**
- [ ] The other 14 files pass unchanged. If any needed a source change, say so explicitly and
      justify it — this card is a configuration fix, and a spreading diff means something else
      is wrong.
- [ ] `npm run verify` green, output pasted (typecheck, lint, test, build).
- [ ] `npm run check:api-drift` green — this card must not move the generated client.

`.env.example` is explicitly non-secret ("Nothing secret belongs here"), so its VALUES are safe to
mirror. Do not invent a seventh variable, and do not change `env-values.ts`'s schema — the schema

so in your report and it will be carded separately as drift.
