## Goal

An administrator can open rooms for a session — one at a time mid-term, or all of them in three
clicks when a session opens — and every part of the system that names a class gets the same
composed display name from the same function.

## Contract delta

All additive. **Every privilege constant already exists** (`Arm.View/Create/Update/Delete`,
`Arm.FormTeacherAssign`, `Arm.CapacityOverride`) — do not invent codes or touch the register.

|---|---|---|
| `GET /api/v1/arms` | `arm.view` | Filtered by session, level, label, status, form teacher. Returns composed display names. Cursor-paginated per §9.5. Default sort is level `progressionOrder` then label **collated naturally** — not alphabetical (6.4.5). |

## Acceptance criteria

- [ ] Arm is a **per-session record** (6.4.7): Primary 2A in 2026/2027 and in 2027/2028 are
      different rows. A test asserts both can exist simultaneously.
- [ ] `displayName` is composed at read time and **never stored**, by exactly one function with
      exactly one implementation. Single alphanumeric label → no space (`Primary 1A`); anything
      else → one space (`Primary 1 Gold`). A test greps the solution for a second implementation
      and fails if one exists. A level with a single arm still renders level + label.
- [ ] Label uniqueness within `(class_level_id, session_id, lower(label))` enforced by a
      **unique index** as well as application validation (6.4.8), with a concurrency test proving
      the index — not the validator — rejects the second of two simultaneous inserts.
- [ ] Single-letter labels normalise to uppercase on save; multi-character labels keep case typed.
- [ ] Arm creation rejected against a `closed` session, permitted against `upcoming` or `active`
      (6.4.3), and rejected under an inactive level while existing arms under one survive (6.4.7).
- [ ] Capacity is a **soft limit** (6.4.6). Over-capacity warns, never blocks. Reducing capacity
      below current occupancy is allowed with a warning and removes nobody. `arm.capacity.override`
      is wired but the enrolment path that consumes it is Phase 2 — mark that seam, do not fake it.
- [ ] Bulk creation: labels continue from the highest existing label, so a second run over a level
      holding A and B creates C. `dryRun` writes nothing — asserted by row count, not by response
      shape. Levels set to zero arms are skipped. Whole run is one transaction.
- [ ] Arms move to `closed` automatically when their session closes, and a closed arm rejects
      every mutation (6.4.7).
- [ ] **Drift 1 resolved:** `POST /terms/{id}/open` enforces "at least one arm exists for the
      session" with the naming message, not a bare 409. `OpenTermHandler.cs:16`'s `DEFERRED`
      comment rewritten to record that it now holds.
- [ ] **Drift 2 resolved (arm half only):** `SessionDto`/`SessionDetailDto` carry a real arm count.
      Pupil and publication counts stay absent — `SessionDto.cs:34`'s comment is narrowed to those,
      not deleted, and the drift entry is re-dated rather than struck whole.
- [ ] `openapi.json` regenerated via `scripts/generate-openapi.ps1 -Promote`; `CONTRACT.lock`
      updated; all ten §9 gates green with the `SUMMARY` block pasted.

## Notes for the implementing agent

Read `product-specification/06-module-class-levels-arms.md` §6.4.3, 6.4.5, 6.4.6, 6.4.7 and 6.4.8
in full first. Read TASK-0038's card too — it is the level half and it establishes where this
module lives (`Domain/Classes/`).

The display-name rule is the one to be pedantic about. Spec 6.4.3 spends a page on it because the
failure mode is a parent receiving a result sheet reading `Primary 1 A`. It is used by the arm
list, selectors, score sheets, rosters, pin slips, the portal, PDFs and every export — so it is a
domain function with unit tests, not a formatting helper near a DTO, and it must not become
conditional on how many arms a level has (6.4.3 rejects that explicitly, Appendix A entry 12).

The two drift resolutions are the reason this card is sequenced ahead of TASK-0030. Do them in the
same dispatch as the arm entity — a card that ships arms and leaves `open` still permissive has
recreated the drift it was written to close.

`arm.capacity.override` and the form-teacher-deactivated warning (6.4.8) both point at surfaces
that do not exist yet. Follow TASK-0035's precedent exactly: implement what can be enforced
honestly, mark the rest `DEFERRED` with this card's id and the missing table named, append to
`backend/docs/ASSUMPTIONS.md` §2, and report it for `STATE.md ## Known drift`.
