# TASK-0065 — Make the integration suite runnable without the network

Owner: backend-dev
Depends on: nothing.
Contract impact: **none** — test infrastructure only. No `src/**` change, no endpoint change, no
regeneration.
Status: queued
Reads: `backend/scripts/ci.ps1`; `backend/tests/SchoolManagement.IntegrationTests/` fixture setup
       (whatever resolves `POSTGRES_TEST_CONNECTION`); `.agent/rules/gates.md`

## Goal

The integration suite runs against a hosted Neon Postgres over the public internet, at roughly 8
seconds per test across ~700 tests. A full gate is 45+ minutes, and any network blip — a DNS
failure, a dropped TLS connection — fails tests that have nothing wrong with them and restarts the
run. On TASK-0051 alone this cost three gate runs and produced five failures, three of which were
the network. This card moves the suite onto a local container so the gate is minutes, not an hour,
and a failure means a defect.

## Contract delta

None.

## Acceptance criteria

- [ ] The integration fixture starts a local Postgres (Testcontainers, or a documented
      `docker compose` service) and the suite runs green against it with no `POSTGRES_TEST_CONNECTION`
      set and **the network unplugged**. Prove the last part.
- [ ] `POSTGRES_TEST_CONNECTION`, when set, still wins — the hosted path stays available and
      `ci.ps1`'s existing resolution from `C:\Users\HP\.gras\pg-test.txt` is untouched.
- [ ] One container (or one database) for the whole run, reused across test classes. A
      container per class trades one cost for another.
- [ ] Measured before/after wall-clock for the integration stage, reported in the closing note.
- [ ] A clear failure message when Docker is absent, naming the fallback — not a stack trace.
- [ ] Test COUNT is unchanged and `Skipped` is 0. **A suite that silently skips when Docker is
      missing is the exact defect this project has already paid for once** — it must fail loudly.

## Out of scope

- Any production or `src/**` change.
- Reducing the number of integration tests, or converting any of them to unit tests.
- CI-server configuration. Local developer runs first.

## Notes for the implementing agent

The 8s/test figure is dominated by round-trips to a pooler endpoint, not by Postgres itself — a
local instance should collapse most of it. Measure rather than assume.

The shared hosted database is also why two concurrent runs corrupt state (`rules/gates.md` §4).
A per-run local container removes that hazard as a side effect; say so in your closing note if it
holds, because it would let the orchestrator drop a standing restriction.
