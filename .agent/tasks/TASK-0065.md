## Goal

The integration suite runs against a hosted Neon Postgres over the public internet, at roughly 8
seconds per test across ~700 tests. A full gate is 45+ minutes, and any network blip — a DNS
failure, a dropped TLS connection — fails tests that have nothing wrong with them and restarts the
run. On TASK-0051 alone this cost three gate runs and produced five failures, three of which were
the network. This card moves the suite onto a local container so the gate is minutes, not an hour,
and a failure means a defect.

## The machine, as probed at dispatch 2026-09-16 — read this before you probe anything

`STATE.md`'s toolchain line says `docker ABSENT`. **That line is about the Windows host and it is
now misleading.** Verified facts:

- No `docker`/`podman`/`nerdctl` on the Windows PATH, no Docker Desktop, and **no
  `\\.\pipe\docker_engine`**.
- Docker Engine **29.8.1 is live inside WSL2 Ubuntu**, started as
  `dockerd -H fd:// -H tcp://0.0.0.0:2375`, daemon active, user in the `docker` group.
- **From Windows, `http://localhost:2375/_ping` returns 200 (API 1.56).** Proven with a real HTTP
  call, not inferred.
- **`http://127.0.0.1:2375` does NOT work — only the name `localhost` does.** WSL2 is in NAT mode
  with localhost forwarding, which answers on the hostname path; the IPv4 literal and a raw
  `[::1]` socket both fail. This is the single most important fact on this card.
- `$env:DOCKER_HOST` is set at USER scope to `tcp://127.0.0.1:2375` — i.e. **to the address that
  does not work.** Do not rely on it being correct, and do not edit it: resolve the endpoint in
  code so the next machine works too.
- `postgres:17.6-alpine` is **not cached**. Pull it once while the network is up, before the
  unplugged proof.
- No `dotnet` inside WSL. The test host stays on Windows; only the Docker API crosses the boundary.

**Human ruling: use Testcontainers against this daemon.** Docker Desktop was rejected (multi-GB
install plus a licensing question). Do **not** install anything on the Windows host, do **not**
edit `/etc/docker/daemon.json`, and do **not** change the daemon's bind address — it is already
configured and the WSL-side setup is not yours to move. A `docker compose` service is no longer
needed; Testcontainers' automatic lifecycle is strictly better and is what the fixture already
reaches for.

machine has never taken the container path. Fix that, fix the skip at `:62`, measure, done.

## Acceptance criteria

- [ ] `IsContainerRuntimeAvailable` recognises a reachable daemon over TCP, not just the named pipe.
      Resolve the endpoint in this order and pass it to Testcontainers explicitly
      (`.WithDockerEndpoint(...)` or `TestcontainersSettings`) rather than trusting ambient
      `DOCKER_HOST`: `DOCKER_HOST` if it actually answers → `tcp://localhost:2375` if it answers →
      the named pipe / unix socket. **`DOCKER_HOST` is wrong on this machine, so a run that only
      works because you exported a corrected value by hand does not satisfy this card.**
- [ ] The probe stays cheap. `DatabaseAvailability.cs:48-55` documents why it must not start a
      container to find out: a failed start costs tens of seconds and buries the real message. A
      short-timeout `/_ping` is fine; a blocking, retrying, or unbounded probe is not.
- [ ] With **no `POSTGRES_TEST_CONNECTION` set**, Testcontainers starts `postgres:17.6-alpine` and
      the suite runs green.
- [ ] **Green with the network unplugged. Prove it** — this is the card's whole point, and it is
      NOT a foregone conclusion: WSL2 NAT-mode localhost forwarding surviving a downed physical
      adapter is an assumption. Pull the image first. **If it does not survive, say so plainly and
      do not paper over it** — that outcome is a legitimate result for this card, not a failure to
      hide.
- [ ] `POSTGRES_TEST_CONNECTION`, when set, still wins. `ci.ps1`'s resolution via
      `lib/postgres-test-connection.ps1` from `~/.gras/pg-test.txt` is **untouched** — the hosted
      path stays available, and `Initialize-PostgresTestConnection`'s "already set wins" contract
      and its never-print-the-string guarantee are not to be modified.
- [ ] One container for the whole run, reused across test classes — **verified against the existing
      collection fixture, not rebuilt.**
- [ ] Measured before/after wall-clock for the integration stage, reported in the closing note.
- [ ] A clear failure message when no database is obtainable, naming both fallbacks (the env var,
      and the Docker endpoint it tried) — not a stack trace, not a skip.
- [ ] Test COUNT is unchanged and `Skipped` is 0. **A suite that silently skips when Docker is
      missing is the exact defect this project has already paid for once** — the skip at
      `DatabaseAvailability.cs:62` IS that defect, and this card removes it. It must fail loudly.

## Notes for the implementing agent

The 8s/test figure is dominated by round-trips to a pooler endpoint, not by Postgres itself — a
local instance should collapse most of it. Measure rather than assume. `ResetDatabaseAsync` runs
per test, which is where that per-test cost lives; migrations are paid once in `InitializeAsync`.

The shared hosted database is also why two concurrent runs corrupt state (`rules/gates.md` §4). A
per-run throwaway container removes that hazard as a side effect — **say so explicitly in your
closing note if it holds**, because it would let the orchestrator drop a standing restriction.

**Bounce this card** rather than guess if any of governance §3's six rows is unanswerable from it.
