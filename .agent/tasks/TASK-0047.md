## Notes for the implementing agent

Read `.agent/STATE.md` first (§4.1), then `frontend/src/api/README.md` and `CONVENTIONS.md`.

**The one new trap on this card.** `ListRoleAssignments`'s 200 body is an inline
`array` of `$ref: RoleAssignmentDto` with **no top-level `example`**. That is the exact shape that
cost TASK-0040 a debugging round on `ReorderLevels`: `exampleFor` in `openapi-handlers.ts` only
resolves an example off a `$ref`'d schema or an inline one that names one, so the contract-derived
default handler answers with an empty body instead of an array. Fix it the way TASK-0040 did —
an explicit `server.use(...)` override in that one test. Do **not** touch `openapi-handlers.ts`
and do **not** loosen the assertion. This is not contract drift; the contract owes no example here.

**Corrected 2026-09-09, after the implementing agent caught this card wrong.**
`RoleAssignmentDto.armIds` is **required and non-nullable** — a plain `array`, empty for a
`SchoolWide` grant, non-empty for `ArmList`. Only `CreateRoleAssignmentCommand.armIds`, the
*request* body, is nullable. Either way, do not add client-side logic that infers `scopeType` from
whether `armIds` is empty — the backend owns that (§4.5).

Keep each new test file under `CONVENTIONS.md` §3's 180-line cap; split by route group if needed,
as TASK-0044 did.
