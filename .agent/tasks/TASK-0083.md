## Goal

A class teacher can record the non-academic ratings for their arm's result set. A primary arm gets affective and
psychomotor trait ratings. A nursery arm gets a development-indicator rating, plus an optional comment per indicator.
The two usage gates TASK-0072 left as stand-ins become real. Attendance and remarks are NOT part of this card (see
Out of scope).

## Acceptance criteria

- [ ] `trait_rating` (pupil, trait, result set/term, `rating_scale_point_id` FK) and `development_rating` (pupil,
      indicator, result set/term, `rating_scale_point_id` FK, comment ≤120 nullable) persist. **A rating is a FK to a
      point on the scale its block or domain uses, never a free value.** A point from the wrong scale gets a 422.
- [ ] An entry surface per result set (GET) returns the pupils down one axis and the ACTIVE traits or indicators on the
      other, with the current ratings and the scale's points/legend. For nursery it also carries the arm's
      active-indicator total, so the client can show the >60 warning.
- [ ] Bulk save (PUT) per result set, whole grid or partial per the approved delta, with idempotency and CSRF like the
      score sheet. It is allowed only while the result set is Draft or Returned for Correction (§6.7.11), else 409.
      Privilege `result.trait.enter`, arm-scoped (it already exists) for both sheets, unless R3 rules otherwise.
- [ ] Which sheet an arm gets follows ruling **R1**, never a hard-coded section name.
- [ ] An indicator or trait added mid-term shows on the next GET. An archived one disappears from new entry, and its
      existing ratings are kept.
- [ ] `ITraitUsageGate` and `IDevelopmentIndicatorUsageGate` become real queries. Removing a rated trait or indicator
      from settings now returns TASK-0072's 409 messages. Prove each with an integration test.
- [ ] Changing a block's or domain's `ratingScaleId` once ratings exist follows ruling **R2**.
- [ ] The completeness counts for ratings (rated pupils / total, per §6.7.5's counters) are computable from what this card
      stores. The gate itself is a later card.
- [ ] The contract delta is approved before implementation (approved 2026-09-19), the orchestrator promotes it once at the end, and the
      client is regenerated in the same PR.
- [ ] Gates: whole unit project, and integration scoped via `-IntegrationFilter`. Never the full gate.

## Rulings — GIVEN by the human 2026-09-19: R1-A, R2-A, R3-A (each the recommendation below)

- **R1 — Which arms rate traits, and which rate indicators?** Sections are editable records, and traits are not
  section-scoped (TASK-0072 ruling). Recommended: an arm rates the development domains of its section, if any, AND
  rates traits only if its section has `ratesTraits = true`. That is a new boolean on `section`, seeded Primary=true,
  Nursery=false: an additive change to `SectionDto`.
- **R2 — A scale changed after ratings exist.** Recommended: refuse the settings save with 409 while any rating in an
  open (not Published) result set uses the old scale's points.
- **R3 — Privilege for nursery ratings.** Recommended: reuse `result.trait.enter`. The spec names no separate
  privilege.
